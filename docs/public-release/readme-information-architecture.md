# Framewright 4.1.1 — README Information Architecture

**Status:** Approved public-release presentation structure

The README is organized for a first-time visitor first, then for a user who
wants to install the Skill, and finally for a maintainer who needs release and
license detail.

## Sequence

1. **Hero / identity** — name, one-line identity, and `You direct. Framewright
   compiles.` establish what Framewright is and who remains authoritative.
2. **What is Framewright?** — explains the difference from a syntax-first
   prompt generator in plain language.
3. **You direct. Framewright compiles.** — makes the human/system boundary
   explicit with a two-column responsibility table.
4. **How it works** — shows the Production Spine as the central compiler state
   with independent artifact branches and one active stage at a time.
5. **Current model routes** — lists only the registered 4.1.1 image and video
   routes, with create/edit distinctions.
6. **Quick Start** — gives a five-step first-use path without exposing the
   entire internal schema.
7. **Personal by design** — explains the tuned-instrument identity and invites
   study, forking, and adaptation.
8. **Design principles** — provides six high-level orientation rules.
9. **Installation** — gives the Skill location and explicit invocation.
10. **Repository structure** — routes readers to the public technical areas.
11. **Versioning and development** — moves source-of-truth and snapshot policy
    below onboarding.
12. **License, attribution, and third-party notices** — separates original
    Framewright terms from identified adapted MIT material and clarifies that
    software attribution is not a final-film credit requirement.

## Editorial constraints

- Keep the first screen compact and free of Desktop mirror, synchronization,
  and internal source-of-truth maintenance detail.
- Prefer calm production language over startup marketing language.
- Keep the director-authority boundary visible before any implementation detail.
- Describe the workflow as branching and stage-independent; never as a
  mandatory Storyboard → Keyframe → Video funnel.
- Preserve the exact 4.1.1 registered model routes and avoid implying support
  for unregistered models.
