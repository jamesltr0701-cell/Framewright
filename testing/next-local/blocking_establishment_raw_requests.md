# Blocking planning requests

These are fictional, planning-only requests. Each case is independent. Apply the candidate Framewright Skill to the request as written; return a compact production reading and shot-plan recommendation, including any decision genuinely needed. Do not compile prompts, generate media, inspect production projects, install the candidate, or start another stage. Do not assume a real provider capability. Where given, reference capabilities are explicit hypothetical test-surface facts.

## B01

我只有这段戏：阿岚和阿乔隔着餐桌坐着，阿岚在门附近，阿乔背后是窗。阿岚问她什么时候离开，阿乔不回答，阿岚把钥匙推到她面前。两人留在座位上。请用 Framewright 帮我构思镜头，20 秒，可以设计镜头顺序，我倾向后面靠近人物。准备整段一次生成。先给方案，不写正式提示词。

## B02

用 Framewright 帮我看这组安排是否能执行：12 秒、三个固定近景，第一镜阿岚问话，第二镜阿乔沉默，第三镜阿岚放下钥匙；这是我锁定的镜头数、开场和时间。阿岚在餐桌靠门一侧，阿乔在靠窗一侧，两人相对坐着，人物单独肖像作为身份参考，没有两人在同一空间的画面。一次生成。先说执行建议。

## B03

用 Framewright 规划一个 9 秒、三个细节镜头的小段落：刷子蘸颜料、刷毛划过纸面、湿颜料缓慢洇开。画面里只有同一只手和工具，没有人物对话，三镜不承担场地介绍。镜头顺序已定，先检查可执行性。

## B04

用 Framewright 帮我构思 15 秒悬念戏。镜头一直只看阿岚在走廊尽头的脸和手，阿乔在门后说话，我们到最后一秒才知道她在里面。保持这个信息揭露顺序，不能提前看见阿乔，也不能用开场镜头让观众猜出门后有人。走廊和门的位置清楚。一次生成，先给镜头建议。

## B05

用 Framewright 先规划这一镜：阿乔坐在餐桌靠窗那侧，面对桌子另一侧靠门的阿岚。现在只生成阿乔的紧近景，她抬眼看对面，再把钥匙收进掌心。之前另一次生成的双人全景里，两人的位置是对的；这次不上传那条全景，也不上传截图或分镜，只上传阿乔的身份肖像。假设这个测试入口只接受身份肖像，不支持站位图或视频作为参考。后面我会把两条剪在一起。先说怎么保证衔接，别写正式提示词。

## B06

用 Framewright 规划单独生成的阿乔紧近景：她在餐桌靠窗侧，阿岚在对面靠门侧，她伸手收起面前的钥匙。用户已接受并明确允许上传一张双人全景截图，仅供座位、距离和视线关系；人物身份仍由阿乔肖像提供。这张截图不是本镜首帧，我不要本镜从全景开始。假设测试入口明确支持站位图片参考。先给参考分工和本镜安排，不执行生成。

## B07

用 Framewright 规划这场戏，24 秒，可以安排镜头。开头已有双人中景：阿岚靠门、阿乔靠窗，两人面对面站着。阿乔随后绕过阿岚，站到门边，阿岚转身面对她，接下去用紧景别拍争论。整段一次生成。镜头必须保留这次移动，我希望移动后的位置清楚，别把后面的站位又恢复成开头。先给建议。

## B08

用 Framewright 帮我制定这一段的拍摄方案。我接受在正片前加 2 秒双人全景，只供站位，后期剪掉；成片仍是 12 秒，生成共 14 秒，正式镜头的对白和节奏已经锁定。两人隔桌坐着，阿岚靠门、阿乔靠窗，正片从阿岚近景问“你什么时候走？”开始，对方沉默，再切她看钥匙。全景时两人静坐，不开始对白或关键动作，进入正式镜头后才问话。整段一次生成。先给镜头、声音和剪除安排，不写正式提示词。
