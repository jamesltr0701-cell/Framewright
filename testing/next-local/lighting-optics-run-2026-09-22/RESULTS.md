# 光照与光学迭代：实际编译及六张图测试

日期：2026-09-22。结论：已修正审计发现的范围错误、加载索引和可恢复性缺口；新增规则已获得实际编译与有限视觉测试证据。**本次没有证明新版普遍优于旧版。** 两版均能处理本组核心编译判断，首轮图像对比有胜有负，局部／全场景编辑范围测试各一次视觉通过。

## 实施修正

1. GPT Image 2.5 edit adapter 从“所有仅改光照都保护背景曝光”改为“保护本次授权范围之外的属性”。局部人物修光可锁房间；全场景修光可改变人物和房间。底层结构/材质受保护，但允许它们的阴影与受光外观发生合理变化。
2. Core craft 索引、camera-motion 与 light-sound 的入口同步新增静态摄影触发条件，避免正文有规则而入口只谈动态镜头。
3. image-master 早先三份安装文件的新增内容已纳入版本化恢复补丁 `versions/iterations/image-master-lighting-optics-2026-09-22.patch`。在当前安装副本做反向 dry-run、在重建的改前副本做正向 dry-run，均通过。没有实际回退安装副本，也没有猜测或新建另一份 canonical skill。

## 实际编译证据

两个独立上下文分别读取旧版 main 的源文件副本及修正后的候选源，执行相同的 [原始请求](raw-requests.md)，没有提供预期答案、补丁或上一轮报告。完整实际回复和生成用 payload 分别在 [control](control/responses.md) 与 [candidate](candidate/responses.md)。不是沿用上轮人工规则走查。

逐项核对 B01–B14：**两版均未发现目标行为违反；本组未测得通过率提升**。关键真实行为包括：

- B05：两版都识别 36 mm 宽裁为21:9、110–135 mm、3.5–4 m 只能给出约0.40–0.56 m的垂直视野，不能同时容纳硬锁的0.85 m；均提问而没有擅改导演锁。
- B06：同样冲突的数字若来自编译器，两版都主动撤回数字，保留完整腰上构图与压缩意图，没有制造新审批。
- B04：两版都得出固定东侧窗在相机A画左、相机B画右，主体解剖右侧保持不变。
- B01/B02/B08/B12：均保留均匀顶光、暗面、可读背景和非写实深焦选择。
- B11：均把背景变锐判为保护项漂移，明确这是导演报告而非自行像素观察；未自动重试。
- B13/B14：均分别保留局部修光的环境锁和全场景修光的环境变化权。这里的控制组是正式4.1.2，未含上轮曾引入的过严背景锁；不能据两者一致就说那条错误规则无害。

候选的表达更明确，例如 G1 分开局部轮廓光、房间反射与整体曝光，G2 用远机位和视场承载压缩意图，B03 对身份源的焦点与近摄视点作明确排除。这是输出内容差异；在本组任务中，旧版也已能保留主要意图，故不转写成已证实的性能优势。

两版 G1/G2 及其可编译的文本片段通过现有图像文本 validator。B13/B14 初始是无真实图片绑定的文字测试，正确记录 `image_edit_prompt_requires_trace`，未伪造 PASS。进入实际编辑前，父执行器提供真实测试母图和独立授权范围，新增 [edit-traces.json](edit-traces.json)，调用现有 `validate_clean_master_edit` 后两项均无错误。

## 实际生图结果

预先记录 [协议](protocol.md) 后，原样提交四个 G1/G2 payload：相同内置工具、无参考图或额外提示词，分别各一张。随后从同一张合成测试母图 `plate_C.png` 独立做两种编辑，未串接编辑像素。共6次调用、6张输出、0重试。没有 THE WEAVER 输入或状态改动。

| 测试 | 旧版 | 修正版 | 可支持的判断 |
|---|---|---|---|
| G1 逆光人物 | [B](media/plate_B.png)：部分通过；脸颈受光较宽、身体偏向镜头 | [C](media/plate_C.png)：部分通过；头更转离镜头、轮廓更接近目标，脸颈仍有较宽亮面 | 此样本修正版更接近姿态/轮廓意图，但两者未完全实现严格窄边光；不宣称普遍改善 |
| G2 前景尺度与焦点 | [D](media/plate_D.png)：可观察核心关系通过，锅的柔焦更明显 | [A](media/plate_A.png)：可观察核心关系通过，锅较清楚但仍软于脸 | 未见修正版优势；两者取景略宽于严格腰上，真实距离/焦段无法由图证明 |
| 仅人物修光 | 无旧版图对照 | [subject](media/edit_subject.png)：视觉通过；人物明显变暗，房间与亮窗近似保持 | 修正版能执行局部范围，不是旧新版相对效果证明 |
| 全场景修光 | 无旧版图对照 | [whole](media/edit_whole.png)：视觉通过；人物、墙面、工作台和窗景一起暗且冷 | 修正版允许已授权的环境变化，没有被错误背景锁卡住 |

另一个独立评审上下文只看到匿名图片、原始场景要求和保护项，没有版本映射或源码。其完整 [视觉评审](blind-visual-review.md) 已保留。父执行器认可“G1部分通过、G2核心关系通过、两种编辑范围通过”的保守结论。G1的“dim with some material visible”本身允许有限材质信息，不能把所有可见衣纹都判作失败；真正短板是较宽脸颈亮面及未充分转离的躯干。没有据这几张图继续堆叠全局禁令。

编辑采用相同尺寸、同一原图；辅助读取相同像素矩形的平均编码RGB值，结果在 [pixel-observations.json](pixel-observations.json)。例如：

| 区域（0–255平均通道值） | 原图 | 仅人物编辑 | 全场景编辑 |
|---|---:|---:|---:|
| 窗区域 | 246.68 | 246.49 | 151.11 |
| 左墙区域 | 59.38 | 59.37 | 30.61 |
| 工作台区域 | 71.01 | 71.58 | 29.06 |
| 脸颈区域 | 71.97 | 42.92 | 30.96 |

这些数值辅助说明变化落在哪些画面区域，不代表lux、曝光档数、真实光比，也不证明逐像素保真。背景在局部编辑中仍有小幅像素变化；已保留差值数据，没有称作硬遮罩编辑。

## 可复核记录与限制

- [源身份](source-manifest.md) 区分两份同标4.1.2但内容不同的测试源；[生成清单](generation-manifest.json) 保存六份实际 Prompt 哈希、工具原始输出、本地副本、图片哈希及尺寸。G1及编辑1672×941，G2为1916×821。
- 模型实现、seed、quality和精确输出尺寸参数未由工具开放。两组各一张，不能隔离采样随机性；图像对比属于探索性证据，不能标作指定API模型的受控因果A/B。相同日期、同一工具不保证底层实现可锁定。
- 当前测试使用简单无参考场景；多资产竞争、肤色与材质长期稳定性、真实THE WEAVER参考栈、MJ V8.2和跨场景复现尚未生图验证。
- 相关回归仍128/128，加载索引与编辑保护范围改后通过。没有新增关键词测试来冒充行为验证。
- 图片保存在本地测试目录，受仓库既有图片忽略规则保护，未放入Git；Prompt、报告、协议、恢复补丁及SHA-256已纳入版本控制。迁移需另外复制该目录的media。
- 本轮完成的是本地候选修正与有限测试，没有发布、更新正式安装版/镜像或推送GitHub。正式Framewright三地同步在发布时处理。

下一阶段适合在真实项目中做受控试用，重点观察复杂参考栈的光照与焦点漂移。当前证据足以说明规则可执行和范围修正有效，但不足以宣称整体成功率已经提高；不为追求一个胜出样本继续追加生成。
