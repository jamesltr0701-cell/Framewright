# Framewright v3.2-v3.4 实施报告

## 1. 实施结论

本轮已依据《Framewright 统一迭代规格与审批制冲突报告》及用户最终批准记录，完成 Framewright `3.2.0 -> 3.3.0 -> 3.4.0` 的顺序实施。

实施遵守以下边界：

- 以 `3.1.0` / commit `9e4438e02ff231e1ebf4806b65cf5fb4241352d6` 为冻结基线；
- 不重写历史 prompt、storyboard、keyframe、video prompt 或项目产物；
- 不修改现有未跟踪的 `Framewright/`、`output/`、`outputs/`、`storyboard/` 目录；
- 不调用外部图片或视频生成；
- 不创建 Pull Request；
- `references/framewright.md` 保持最高权威，Seedance 2.5 profile 为从属 adapter。

## 3. 3.2.0 实施内容

- 在 Scene Grammar 与 Production Spine 之间加入 Visual Strategy Pass。
- 明确 AUTEUR、APPRENTICE、SCREENWRITER 对 Visual Strategy 的不同权限。
- 扩展 Committed Shot 的 composition、depth/occlusion、information control、scene-rule relation 和 previous-shot relation。
- 将依赖顺序锁定为 `Shot / Phase Spine -> Panel Evidence -> Board Feasibility -> Layout`。
- 分离 shot count、phase count、panel count、board count、grid-cell count。
- Panel Evidence Plan 成为 `panel_count` 的唯一内部真相来源。
- 保留 5、7、8、13、20 等所有 evidence-derived panel count；不把八格本身视为缺陷。
- 执行 C01：一个 approved GU 最多一张 board，不支持 board series；board pressure 只能请求 GU review，不能自动拆分。
- 执行 C06：resolved Storyboard stage 保存 `prompt_storyboard.txt` 并授权恰好一次初始 board generation；retry、修订后重生和 variant 需要新授权。
- Keyframes 与 Video Prompt 保持 prompt-only。

## 4. 3.3.0 实施内容

- 按 C03 将 `uploaded_visual_assets` 一次性替换为统一 `uploaded_assets`；未保留 compatibility field 或 sibling registry。
- 建立 image / video / audio 共用的 Material Registry。
- 将 `reference_lifecycle` 定义为 master record 内部 view；Production Spine 的 active/planning lists 为 freeze-time derived views。
- 增加从属 `references/runtime_profiles/seedance_2_5.md`，并在 Skill 中设置严格条件式完整读取。
- 分离 Framewright director mode 与 Seedance `ui_mode` / control profiles。
- 建立 Omni Reference、Smart Edit、Long Video、First and Last Frames、Extend 的 router 与基础 schema。
- 将 Seedance 2.5 的 30 秒定义为 capability ceiling，而不是默认时长或 feasibility 证明。
- 将 Run Card 并入 assistant-facing handoff；只保存 clean prompt，不默认创建 `run_card.md`。
- 强化 storyboard planning-only 与 explicit runtime admission 边界。

## 5. 3.4.0 实施内容

- 将 Seedance `@` 定义为 surface-specific material-selection operation，而不是稳定词法 handle。
- 区分 UI interactive mention、`.txt` plain-text surrogate 与 API asset binding。
- 由 Run Card 将 `@Image 1` / `@Video 1` / `@Audio 1` 映射到稳定 Material Registry role 和具体文件。
- 允许无歧义的单一 material mention 直接作主语；多主体时只加入最短必要限定。
- Seedance task-specific schema 成为当前 prompt 的唯一 serialization owner；不与 generic fallback headings 重复。
- 保留未指定声音时的 core 默认：环境声 + 同步 diegetic/action SFX + no music。
- 仅在用户明确提出时启用 dialogue、audio reference/edit、music、SFX、subtitle/visible-text policy，并限制在请求范围内。
- Smart Edit 保持 source video 为 sole editing master。
- 增加 route prerequisite、surface support、character-limit 和 advanced feasibility validation。
- 增加 generation evidence 结构及 planning / serialization / rendering / reference authority / runtime or surface / model behavior 分类。
- 规定 repair 只作用于最小 scene-local scope；一次 lucky generation 不升级为 global rule。
