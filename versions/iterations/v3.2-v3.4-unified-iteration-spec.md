# Framewright 统一迭代规格与审批制冲突报告

## 0. 文档状态与使用边界

本文是一份可用于后续完整迭代的实施规格，但当前状态仍是 `Planning Only`。

创建本文不代表已经授权修改以下现有文件：

- `skill/framewright/SKILL.md`
- `skill/framewright/references/framewright.md`
- 任何现有 `versions/iterations/*.md`
- 任何历史 prompt、storyboard、keyframe、video prompt 或生成结果
- 任何用户项目目录

只有在本文末尾的 Contradiction / Redundancy / Clarification Report 得到用户逐项批准，并且用户再次明确要求执行后，实施者才可以开始修改 Framewright。

若实施过程中发现本文没有列出的新冲突、冗余、语义漂移或兼容性风险，必须：

1. 停止受影响部分的修改；
2. 保留当前 3.1.0 行为；
3. 将问题追加到审批报告；
4. 等待用户决定；
5. 不得以“顺便优化”“统一措辞”或“清理旧规则”为由自行处理。

本文采用以下权威顺序：

1. 用户最新明确批准的产品边界和导演控制原则；
2. Framewright 3.1.0 authoritative specification；

4. Seedance 2.5 适配路线图；
5. 历史版本与旧 prompt，仅作为比较和回归证据。

## 1. 迭代目标

本次完整迭代同时处理三个相互关联、但不能互相替代的问题。

### Track A：Directorial Intelligence

修复 APPRENTICE 和 SCREENWRITER 在镜头信息不足时收敛到安全 coverage 的问题：

- 缺少 scene-level camera premise；
- shot function 可能只为普通构图事后辩护；
- 镜头序列有事件顺序，却没有摄影句法；
- renderer 或 reference pose 可能进一步放大正面、居中、3/4 展示构图。

### Track B：Storyboard Structure Intelligence

修复 shot、phase、panel、board、grid cell 没有明确分层后产生的结构默认：

- 用户没有提供数量时，系统可能安全地收敛到 8 panels；
- 2×4 grid 可能在无意中反向影响 shot 或 phase 结构；
- continuous-take phases 可能被错误理解为 cuts；
- 复杂序列可能为了塞进一张 board 而欠采样；
- 简单序列可能为了填满网格而产生 filler coverage。

### Track C：Seedance 2.5 Runtime Adaptation

让 Framewright 在不污染 director mode 和 core production logic 的前提下理解：

- Seedance task route；
- mixed-media material authority；
- task-specific execution schema；
- Run Card 与 pasteable prompt 的边界；
- storyboard、keyframe、video、audio 的运行时映射；
- validation、feasibility、generation evidence 与 cost。

## 2. 核心产品结论

Framewright 3.1.0 不应被重写。其核心身份继续保持：

> 一个 director-steered、asset-aware 的 AI filmmaking prompt compiler 与 production-planning copilot。

本次迭代采用 `additive first` 原则：

- 能通过新增中间层解决的问题，不改旧规则；
- 能通过明确 owner-of-truth 解决的冗余，不删除旧能力；
- 能通过 adapter 解决的模型差异，不写进 director core；
- 只有出现真实逻辑冲突或双重真相来源时，才提出修改或删节；
- 所有修改或删节必须经过本文末尾的用户审批。

目标架构：

```text
Director Intent and Explicit Locks
    ↓
Unified Director Intake
    ↓
Director Mode + Scene Grammar
    ↓
Visual Strategy
    ↓
Committed Shot / Phase Spine
    ↓
Panel Evidence Plan
    ↓
Board Feasibility + Storyboard Layout
    ↓
Optional Explicit Storyboard Runtime Admission

Committed Production Spine
    +
Multimodal Material Registry and Authority Map
    ↓
Seedance Runtime Profile + Task Router
    ↓
Task-Specific Execution Schema
    ↓
Assistant-Facing Run Card + Clean Pasteable Prompt
    ↓
Validation + Generation Evidence Loop
```

- 删除；
- 合并；
- 改写其语义；
- 改变默认行为；

## 4. Evidence Baseline

### 4.1 Blandness 证据

当前审计结论：

- overall artifact blandness：material；
- primary root cause：Visual Strategy Missing；
- secondary causes：局部 Shot Spine Coverage Collapse、reference-authority serialization gap、Rendering Collapse、Reference Contamination；
- 不是所有固定、eye-level、3/4 或重复构图都有问题；
- Havoc 的连续环绕和 Freefall 的阶段采样是反向控制；
- AUTEUR 用户锁定镜头不得被拿来证明系统主动设计能力，也不得被修复模块改写。

### 4.2 8-panel 证据

已统计 75 个 `prompt_storyboard.txt` 文件实例，其中包括历史副本和重复项目：

- 5 panels：16 份；
- 8 panels：12 份；
- 10 panels：12 份；
- 其余从 2、3、4、6、7、9、11、12、13 到 20 均存在。

因此不应建立“禁止八格”规则。

真正的重复信号是：在用户没有锁定 panel 数的近期独立单元中，Blade、Havoc、Freefall 都由系统选择了 8 panels。三者结果不同：

- Blade：八格欠采样并伴随镜头设计不足，用户要求更多 shot 和 camera movement；
- Havoc：八个 phase 可合理表达一条连续顺时针环绕；
- Freefall：八个 phase 形成了有效的视觉句子；
- 已明确锁定八格的项目必须保持八格。

成功指标不是降低八格比例，而是系统能解释为什么某个 scope 应为八格、非八格或多 board。

### 4.3 Seedance 2.5 证据边界

- 当前适配依据是 2026-08-08 的官方文档快照和现有路线图；
- UI mode、native syntax 和 capability 应进入 versioned runtime profile；
- 官方 guide 是推荐用法，不是模型行为的最终证据；
- 任何运行时规则都必须经过 canonical case 与真实 generation evidence 验证；
- 一次 lucky generation 不得升级为全局 core rule。

## 5. Track A — Directorial Intelligence Specification

### 5.1 Visual Strategy Pass

建议在当前 `## 6. Scene Grammar Routing` 与 `## 7. Production Spine` 之间新增一个 subsection，不重写 Scene Grammar：

```yaml
visual_strategy:
  dramatic_alignment:
  viewer_knowledge:
  spatial_pressure:
  camera_attitude:
  dominant_compositional_rule:
  reveal_or_withhold_policy:
  camera_progression:
  rupture_point:
  production_feasibility:
```

职责：

- 描述 scene-level viewer relationship；
- 在 Shot Spine 之前建立一条可说明的 camera premise；
- 规定一条 dominant rule 和必要时的 exception；
- 不输出到 model-facing prompt，除非被转译成具体构图、动作、视点或 camera carriers；
- 不代替 scene grammar、camera logic、cinematography 或 shot-level execution。

### 5.2 Mode-specific authority

#### AUTEUR

- Visual Strategy 只用于理解、验证和检测执行偏差；
- 不改变 shot order、count、framing、movement、rhythm 或 panel structure；
- renderer / serializer 不服从时，只修执行层。

#### APPRENTICE

- 从用户已有 shot intent 推导 visual premise；
- 未锁定镜头必须延续、发展或有意识地反衬该 premise；
- 不将缺失 camera data 自动填成 neutral default；
- 如果新增会改变 core rhythm、shot count、panel count、board count 或 GU boundary，按现有 authority gate 处理。

#### SCREENWRITER

- 在 committed Shot Spine 前主动形成 camera premise；
- 从 drama、subjectivity、information、space、performance 与 feasibility 推导镜头；
- 不从 generic coverage list 开始；
- 保留剧情、动作因果、blocking、continuity、performance progression 和 GU boundary。

### 5.3 Committed Shot extension

建议扩展而不删除现有字段：

```yaml
committed_shot:
  shot_id:
  editorial_function:
  attention_function:
  camera_relationship:
  composition_strategy:
  depth_or_occlusion_strategy:
  information_control:
  relation_to_scene_rule:
  relation_to_previous_shot:
  start_state:
  visible_action:
  end_state:
  continuity_dependencies:
```

新增字段只对 compiler-inferred 或 compiler-improved 结构强制；AUTEUR 用户没有提供的字段不得反向成为改镜头的理由。

### 5.4 Creative validation

新增：

- Scene-Level Camera Premise Test；
- Default Coverage Substitution Test；
- Repetition and Rupture Test；
- Visual Sentence Test；
- Function-Label Laundering Test；
- Reference Pose Contamination Test。

明确不做：

- 不规定高角度、低角度、广角、特写或 movement 数量；
- 不用 orbit、drone、Dutch angle 或极端广角伪造风格；
- 不将静态、eye-level、对称或重复自动判为低质量；
- 不让 style reference 代替 camera premise。

## 6. Track B — Storyboard Structure Intelligence Specification

### 6.1 五类数量必须分离

```yaml
storyboard_structure_counts:
  shot_count:
  phase_count:
  panel_count:
  board_count:
  grid_cell_count:
```

- `shot_count`：剪辑意义上的镜头数量；
- `phase_count`：一个连续镜头内部需要识别的状态或摄影阶段；
- `panel_count`：为了证明结构而选择的冻结瞬间数量；
- `board_count`：需要几张 storyboard board；
- `grid_cell_count`：每张 board 的布局容量。

任何两项都不得自动等同。

### 6.2 Panel Evidence Plan

建议在 committed Shot Spine 之后、storyboard layout resolution 之前增加：

```yaml
panel_evidence_plan:
  count_source:
    director_locked | shot_spine_derived | phase_sampling | renderer_split
  shot_count:
  phase_count:
  panel_count:
  board_count:
  mappings:
    - panel_id:
      maps_to_shot_or_phase:
      proof_obligation:
      frozen_instant:
      camera_carriers:
      state_before:
      state_after:
```

### 6.3 固定推导顺序

1. 锁定或推断 Shot / Phase Spine；
2. 列出必须由 storyboard 证明的 action、state、information、geography、contact、performance 与 camera change；
3. 为 proof obligations 选择 drawable frozen instants；
4. 得到 panel count；
5. 运行 Board Feasibility Gate；
6. 得到 board count；
7. 最后选择每张 board 的 grid 与 blank cells；
8. serializer 将已决定的数量复制到 model-facing Layout Contract。

禁止：

- 从 2×4 grid 倒推八个镜头；
- 从总时长机械推导 panel 数；
- 将 panel 数作为 shot 数；
- 将 continuous-take phases 序列化成 cuts；
- 为填满 grid 添加 filler coverage；
- 为保留单 board 而删除 critical states。

### 6.4 Board Feasibility Gate

在 panel count 已经由内容决定后评估：

- panel 是否仍可读；
- camera carriers 是否在缩小后可辨认；
- 字体、masthead、gutter 是否挤压画面；
- target storyboard renderer 对该 panel density 是否可靠；
- 是否需要 board series；
- 增加 board 是否带来额外生成成本。

如果建议多 board：

- 不改变 shot、phase、panel 或 GU 结构；
- 不静默生成；
- 说明 board count、每张覆盖范围、成本与理由；
- 等待用户批准；
- 文件和单 artifact 合同按 C01 的批准结果执行。

### 6.5 Structure validation

新增：

- Count Provenance Test；
- Grid Independence Test；
- Panel Necessity Test；
- Under-Sampling Test；
- Filler Panel Test；
- Shot–Phase–Panel Mapping Test；
- Eight-Panel Default Test；
- Board Legibility Test；
- Board Split Is Not GU Split Test。

验收不使用“八格比例下降”作为 KPI。

## 7. Track C — Seedance 2.5 Runtime Adaptation Specification

### 7.1 Core / adapter boundary

Framewright core 继续负责：

- director intent；
- explicit locks；
- mode 与 scene grammar；
- Production Spine；
- Visual Strategy；
- Shot / Phase / Panel logic；
- continuity、performance、sound、reference authority；
- stage 与 GU boundaries。

Seedance adapter 负责：

- model version；
- task route；
- UI mode / control profiles；
- native reference tokens；
- task-specific execution schema；
- model-facing serialization；
- target-specific validation 与 capability profile。

Seedance adapter 不得覆盖 core 中的导演锁定项。

### 7.2 Runtime profile

```yaml
seedance_runtime:
  model: seedance_2_5
  ui_mode:
    omni_reference | smart_edit | long_video | first_last_frames | extend
  control_profiles:
    - multi_reference
    - multi_keyframe
    - storyboard
    - blockout_coarse
    - blockout_fine
    - seamless_transition
    - marked_edit
    - dialogue_control
    - audio_reference
    - audio_edit
    - subtitle_control
  generation_strategy:
  manual_override:
```

规则：

- director mode 与 Seedance UI mode 永远分离；
- Seedance task 仍属于 Video Prompt stage；
- router 可以推荐，但用户可以 override；
- recommendation reason 留在 assistant-facing Run Card；
- UI instruction 不进入 pasteable prompt。

### 7.3 Multimodal Material Registry

目标 schema：

```yaml
runtime_material:
  media_type: image | video | audio
  native_ref:
  role:
  master_status:
  allowed_authority:
  denied_authority:
  active_stages_or_beats:
  planning_or_runtime_status:
```

核心规则：

- attachment 不自动授予完整 authority；
- identity 不控制 source pose、camera、crop 或 composition；
- motion reference 不自动控制 identity、environment 或 final style；
- audio timbre 不自动控制 dialogue text、emotion、accent 或 pacing；
- Smart Edit 中 source video 是 sole editing master；
- authority 可按 stage / beat 局部生效；
- inactive、withheld、planning-only 与 rejected material 继续遵守 Silent Reference Exclusion。

现有 `uploaded_visual_assets` 与 `reference_lifecycle` 如何迁移，由 C03 与 R04 决定。

### 7.4 Task-specific execution schemas

#### Omni Reference

- generation goal；
- material-to-role map；
- allowed / denied authority；
- active stage / beat；
- shot or phase progression；
- continuity and end state。

#### Smart Edit

```text
EDIT GOAL
SOURCE VIDEO ROLE
TARGET MATERIAL ROLE
EDIT SCOPE
CONTENT TO PRESERVE
```

Source video 是 sole editing master；未授权的 motion、audio、timing、occlusion、event order 必须保留。

#### Long Video

- stage 化；
- 每 stage 一个主要 state change；
- visible entry / end state；
- stage-local dialogue、SFX、reference authority；
- semantic timing；
- 超载仍触发现有 GU Feasibility Gate。

#### First and Last Frames

- first-frame authority；
- last-frame authority；
- middle motion and state change；
- aspect / composition compatibility；
- 首尾素材不控制全部中间 pose 和 motion。

#### Extend

从 source video 的真实结束边界恢复：

- composition；
- identity and pose；
- object / damage state；
- motion direction and momentum；
- camera-subject relationship；
- lighting / environment；
- room tone、reverb、noise floor 与 action-sound continuity。

Extend 与现有 First-Frame Continuation 的关系见 L06。

### 7.5 Storyboard runtime admission

Storyboard 继续 planning-only by default。

只有用户明确批准后，adapter 才能选择：

- full board；
- panel crops；
- selected structural panels；
- multi-keyframes；
- no storyboard attachment。

运行时 mapping 必须说明：

- panel 对应 shot 还是 phase；
- allowed structural authority；
- denied board layout、title、labels、line style 与 sheet geometry；
- continuous take 的 panels 不代表 cuts；
- panel count 不自动转化为 video beat count。

### 7.6 Run Card and pasteable prompt

目标是同时提供：

#### Assistant-facing Run Card

- MODE；
- CONTROL PROFILES；
- DURATION / ASPECT RATIO；
- MATERIALS TO UPLOAD；
- REFERENCE MAPPING；
- GENERATION STRATEGY；
- KNOWN RISKS。

#### Clean pasteable prompt

- 只包含模型需要理解的内容；
- 继续遵守 Runtime Cleanliness；
- 不包含 UI 教程、审批、风险、attachment 操作或 workflow explanation。

保存方式与现有 one-artifact contract 的关系见 C02。

### 7.7 Native syntax and policies

Adapter 可使用：

- `@Image 1`；
- `@Video 1`；
- `@Audio 1`；
- optional music / SFX / dialogue / visible-text markers；
- task-specific preserve / remove / replace policy。

Native syntax 不能进入 core reference identity。现有 `{{HANDLE}}` 与 native tokens 的关系见 L05。

### 8.5 Acceptance criteria

#### Creative

- 三个已知 bland cases 得到可解释改善；
- 不通过随机 angle variety 制造假改善；
- AUTEUR locks 零回归；
- 正确的静态、重复和正面构图仍被保留。

#### Structure

- 每个 inferred panel count 有唯一 provenance；
- grid 变化不改变 Shot / Phase Spine；
- 无 filler panels；
- 无关键状态欠采样；
- Freefall/Havoc 如仍为八格，能通过证据测试；
- locked 八格不改变；
- board splitting 不改变 GU。

#### Runtime

- task route 与目标一致；
- 用户 override 有效；
- 每项 material 有有限 authority；
- source-master violation 为零；
- storyboard 不自动进入 runtime；
- continuous-take phases 不被改成 cuts；
- UI instruction 不进入 prompt；
- inactive references 不泄漏。

#### Reliability and cost

- 平均重试和积分成本不高于 3.1 baseline；
- 高风险任务先验证最不确定 production block；
- lucky generation 不成为全局规则；
- 失败能定位为 planning、serialization、rendering、reference、runtime 或 model behavior。

## 11. Stop Conditions

出现以下任一情况必须停止：

- 需要改变未列入 Change Whitelist 的规则；
- AUTEUR 或其他 director lock 回归；
- panel 数改变但没有 count provenance；
- 只是把 8 换成另一个固定默认数；
- multi-board 增加成本但未获批准；
- renderer 问题被当成 planning 问题修复；
- reference registry 出现两个可独立编辑的 source of truth；
- Run Card 或 UI instruction 泄漏到 pasteable prompt；
- Seedance adapter 改变 director mode、scene grammar、stage 或 GU；
- 新规则与 protected rule 冲突；
- 为了压缩规范而删除语义；
- 为了减少重复而合并了实际承担不同层级职责的字段；
- 无法用测试证明修改没有造成 drift。

## 12. Contradiction / Redundancy / Clarification Approval Report

本节是强制审批门。所有状态默认为 `PENDING`。

用户可按以下格式回复：

```text
C01 = B
C02 = A
C03 = C
R01 = approve clarification
L01 = approve
```

### 12.1 True or material contradictions

#### C01 — One storyboard board / one artifact vs board series

Current rule：

- 每个 storyboard 是一张 16:9 board；
- 每次只执行一个 active stage / artifact；
- 默认文件名是 `prompt_storyboard.txt`。

Proposed pressure：

- 内容决定的 panel count 可能超过一张 board 的可靠可读容量；
- board splitting 不应删除 panel 或拆 GU。

Options：

- A：保持永远单 board；超载时只报告风险，不支持 board series。
- B：允许同一 Storyboard stage 下的 approved board series；每张 board 是独立 prompt artifact，按顺序一次生成一个，使用 `prompt_storyboard_board##.txt`，不改变 GU。`Recommended`。
- C：一个 prompt 文件内批量描述多张 board。该方案容易违反 one-artifact 和 hidden-batch 边界，不推荐。

Status：`PENDING USER APPROVAL`

#### C02 — Run Card + pasteable prompt vs Runtime Cleanliness / one artifact

Current rule：

- 保存的 prompt 文件只能包含可执行 model-facing 内容；
- operator instruction、risk、attachment instruction 和 workflow explanation 不得进入；
- assistant-facing handoff 已存在。

Proposed pressure：

- Seedance 2.5 需要 mode、materials、mapping、UI setting 和 risk 的 Run Card。

Options：

- A：Run Card 成为现有 assistant-facing handoff 的结构化扩展；只保存纯净 `prompt_video.txt`。`Recommended`。
- B：新增独立 `run_card.md` 文件；会改变 one-artifact default。
- C：把 Run Card 与 prompt 放进同一文件；违反 Runtime Cleanliness，不推荐。

Status：`PENDING USER APPROVAL`

#### C03 — `uploaded_visual_assets` vs unified multimodal `uploaded_assets`

Current rule：

- Input Package 只声明 `uploaded_visual_assets`。

Proposed pressure：

- Seedance 2.5 需要 image、video、audio 和 source-video editing master。

Options：

- A：一次性替换为 `uploaded_assets`；最干净，但迁移风险最高。
- B：保留 visual 字段并增加 video/audio sibling lists；兼容但结构重复。
- C：引入统一 `uploaded_assets` 作为新 source of truth，并提供一个有明确删除期限的 compatibility migration；通过回归后再移除旧字段。`Recommended`。

Status：`PENDING USER APPROVAL`

#### C04 — “Do not classify sound into separate routing categories” vs audio task policies

Current rule：

- 默认生成 diegetic sound；
- 默认 no music；
- 不把 sound 分类成独立 routing categories。

Proposed pressure：

- Seedance Smart Edit、audio reference 和 subtitle control 需要区分 preserve/remove/replace、timbre、dialogue、ambience、music、SFX。

Options：

- A：保留默认 sound contract，将旧句澄清为“不得以声音类别改变 director mode、scene grammar 或主 workflow route；adapter 可管理 audio material authority 与 edit policy”。`Recommended`。
- B：删除旧句，让 adapter 完全接管声音；可能导致 core drift，不推荐。
- C：不增加 audio policies；无法完整适配 2.5，不推荐。

Status：`PENDING USER APPROVAL`

#### C05 — One authoritative reference file vs versioned runtime adapter

Current rule：

- Skill 要求完整读取 `references/framewright.md`；
- 当前没有条件式 runtime profile 文件。

Proposed pressure：

- Seedance UI、native syntax 和 capability 会更新，不应持续写入 core。

Options：

- A：把全部 Seedance 2.5 规则写进 `framewright.md`；无需改 Skill，但 core 会膨胀并与模型版本绑定。
- B：新增 subordinate `references/runtime_profiles/seedance_2_5.md`；main spec 仍是最高权威，Video Prompt stage 选择 Seedance 2.5 时由 Skill 额外完整读取 adapter。`Recommended`。
- C：adapter 仅作外部说明，不进入执行链；无法保证稳定使用。

Status：`PENDING USER APPROVAL`

### 12.2 Potential redundancies requiring owner-of-truth decisions

#### R01 — `visual_strategy.camera_progression` vs existing `camera_logic`

Risk：两个字段可能分别被修改，形成不同 camera plan。

Recommended clarification：

- `visual_strategy` 是 scene-level premise、rule、progression、rupture；
- `camera_logic` 是从已批准 premise 派生的可执行 camera summary；
- `camera_logic` 不得反向改变 Visual Strategy。

Status：`PENDING USER APPROVAL`

#### R02 — Extended Committed Shot fields vs attention/spatial/camera fields in Production Spine

Risk：`composition_strategy`、`information_control` 等可能重复 `attention_flow`、`spatial_geography`、`camera_logic`。

Recommended clarification：

- Production Spine fields 保存 scene/GU-level contract；
- Committed Shot fields 保存逐 shot 的具体执行；
- shot-level values 必须派生自 scene-level contract；
- 不删除任何现有 field。

Status：`PENDING USER APPROVAL`

#### R03 — `panel_count` in Panel Evidence Plan vs Layout Contract

Risk：内部 count 与 model-facing count 不一致。

Recommended owner：

- Panel Evidence Plan 是唯一内部 source of truth；
- Storyboard Layout 只复制已批准 count 用于 serialization；
- validation 必须比较两者完全一致。

Status：`PENDING USER APPROVAL`

#### R04 — Multimodal Material Registry vs existing Reference Lifecycle and active/planning lists

Risk：多个 registry 独立记录 role、authority、status。

Recommended direction：

- 统一 material registry 是每项素材的 master record；
- `reference_lifecycle` 作为该 record 的 authority/lifecycle view，而不是第二份 registry；
- `active_runtime_references` 与 `planning_only_references` 是冻结 Spine 时生成的 derived views；
- 是否重命名现有字段必须与 C03 一起批准。

Status：`PENDING USER APPROVAL`

#### R05 — Task-specific schemas vs current compact runtime headings

Risk：同一 prompt 同时被 generic headings 与 task schema 控制。

Recommended clarification：

- current compact headings 是 core fallback；
- adapter 选择 task-specific schema 后，该 schema 成为本次 serialization owner；
- 仍必须满足 core continuity、runtime cleanliness、sound、timing 与 character-limit rules；
- 不在同一 prompt 中重复两套结构。

Status：`PENDING USER APPROVAL`

#### R06 — Blandness audit protocol vs core creative validation

Risk：详细审计协议和 core validation 都包含相同测试，未来可能分叉。

Recommended clarification：

- core 保存简短的 pre-save prevention tests；
- audit protocol 保存 scene-level forensic diagnosis、root-cause classification 和 repair procedure；
- audit protocol 不成为每次普通 compilation 的完整必跑流程；
- 两者共享测试名称和定义，不复制全部说明。

Status：`PENDING USER APPROVAL`

### 12.3 Clarification-only items

#### L01 — Production Spine field order vs execution dependency

Current ambiguity：`storyboard_layout` 在 schema 中列于 `shot_or_phase_plan` 之前，可能被误读为 layout-first。

Proposed clarification：字段列表顺序应改为反映依赖：Shot/Phase Spine → Panel Evidence → Storyboard Layout。该调整不改变旧字段语义。

Status：`PENDING USER APPROVAL`

#### L02 — “Scene grammar controls panel density”

Proposed clarification：Scene Grammar 影响需要多少结构证明和节奏采样，但不直接输出 panel count；Panel Evidence Plan 决定 count。

Status：`PENDING USER APPROVAL`

#### L03 — Board split vs Generation Unit split

Proposed clarification：多 board 只是 planning-image packaging；不产生新的 GU、cut、video prompt 或 continuity reset。

Status：`PENDING USER APPROVAL`

#### L04 — Storyboard planning-only vs storyboard control profile

Proposed clarification：`storyboard` control profile 只表示用户已明确批准 storyboard 成为有限 runtime reference；它不改变 planning-only default。

Status：`PENDING USER APPROVAL`

#### L05 — Core runtime alias vs Seedance native reference token

Proposed clarification：core 可继续用 semantic alias；adapter 在 Run Card 和最终 serialization 中映射到 `@Image 1`、`@Video 1`、`@Audio 1`。Native numbering 不得反向定义素材角色。

Status：`PENDING USER APPROVAL`

#### L06 — First-Frame Continuation vs First/Last Frames vs Extend

Proposed clarification：

- First-Frame Continuation：以 prior final frame 继续同一镜头；
- First/Last Frames：用两张锚点约束一个新生成段；
- Extend：从 source video 的结束边界继续，并保存 visual + audio momentum；
- 三者 authority 和 continuity contract 不可互换。

Status：`PENDING USER APPROVAL`

#### L07 — Eight panels as a valid result

Proposed clarification：八格不是错误类型。只有无 provenance、欠采样、filler、grid-driven 或违反 director intent 时才构成问题。
