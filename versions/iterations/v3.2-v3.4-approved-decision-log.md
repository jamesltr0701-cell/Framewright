# Framewright v3.2-v3.4 Approved Decision Log

This log resolves Section 12 of `v3.2-v3.4-unified-iteration-spec.md`. It records the user's final decisions and overrides any earlier recommendation or provisional status in that planning document.

Implementation remains bounded by the Baseline Preservation Contract. A decision below authorizes only the named exception or clarification; it does not authorize unrelated cleanup, rewriting, migration, generation, or workflow expansion.

## Contradictions

### C01 - One generation unit, one storyboard board

Decision: `A`, superseding the earlier provisional `B`.

- One approved generation unit may produce no more than one storyboard board.
- Board series are unsupported.
- A readable single board may contain a content-derived count such as 5, 7, 8, 13, or 20 panels.
- Board pressure may trigger a Generation-Unit Feasibility review, but it may not directly split a generation unit.
- A new generation-unit boundary requires a natural content boundary and explicit director approval.
- Each approved child generation unit receives its own single board.

### C02 - Run Card remains assistant-facing

Decision: `A`.

- Extend the existing assistant-facing handoff into a structured Run Card.
- Save only the clean model-facing `prompt_video.txt` or approved split-unit prompt files.
- Do not create `run_card.md` by default.
- Do not place UI instructions, risks, approval language, or workflow explanation in the prompt file.
- A saved prompt file remains the default; do not silently replace it with inline-only output.

### C03 - Clean break to `uploaded_assets`

Decision: `A`.

- Replace `uploaded_visual_assets` with unified `uploaded_assets` in one controlled migration.
- Do not retain a compatibility field or sibling registries.
- Image, video, and audio materials enter one normalized material record system.
- Do not rewrite historical prompts or project artifacts.

### C04 - Preserve the v3.1 sound default

Decision: `A`.

- With no explicit sound request, preserve the v3.1 behavior: generate environmental ambience and synchronized diegetic/action effects; do not generate music.
- When the user explicitly requests sound reference, editing, dialogue, subtitle, music, ambience, or SFX control, apply the Seedance 2.5 adapter policy only to the requested scope.
- Audio categories may not change director mode, scene grammar, active stage, or generation-unit boundaries.

### C05 - Versioned subordinate Seedance adapter

Decision: `B`.

- Keep `references/framewright.md` as the highest authority.
- Add `references/runtime_profiles/seedance_2_5.md` and read it only when Video Prompt targets Seedance 2.5.
- The adapter may not override explicit director locks or core production contracts.
- Treat 30 seconds as a target capability ceiling supplied to the Generation-Unit Feasibility Gate, not as a default duration or proof that a dense unit is feasible.
- Never auto-split or auto-merge because the capability ceiling changes.

### C06 - One initial storyboard render

Decision: `A`.

- Selecting and resolving the Storyboard stage authorizes saving `prompt_storyboard.txt` and generating one initial storyboard image from that prompt.
- The prompt and initial image belong to one Storyboard-stage delivery package, not two active stages.
- One generation unit produces one board and no automatic variants.
- A failed-generation retry, prompt revision followed by regeneration, or extra variant requires fresh user authorization.
- Keyframes and Video Prompt remain prompt-only by default.
- A generated storyboard remains planning-only and is not admitted to video runtime without explicit user authorization.

## Owner-of-truth clarifications

- `R01`: Visual Strategy owns the scene-level premise, progression, and rupture. `camera_logic` is its derived executable summary and may not rewrite it.
- `R02`: Production Spine owns scene/GU-level contracts. Committed Shot fields own per-shot execution and derive from the Spine. Do not delete existing fields.
- `R03`: Panel Evidence Plan is the sole internal owner of `panel_count`. Layout copies the approved value. The earlier multi-board supplement is void under C01.
- `R04`: Unified Material Registry is the master record. `reference_lifecycle` is a view of that record; active/planning lists are derived at Spine freeze and are not independently editable.
- `R05`: Generic compact headings are the core fallback. When an adapter selects a task-specific schema, that schema alone owns serialization for the current prompt.
- `R06`: Core carries short pre-save creative prevention tests. The detailed blandness audit retains forensic diagnosis, root-cause classification, and repair procedure.

## Clarifications

- `L01`: Reflect the dependency order Shot/Phase Spine -> Panel Evidence -> Board Feasibility -> Storyboard Layout without changing old field meaning.
- `L02`: Scene Grammar influences proof obligations and sampling pressure but never directly outputs panel count.
- `L03` revised: A generation unit does not split into multiple boards. Board pressure may request GU review but cannot itself create a new GU.
- `L04` revised: C06 governs the initial storyboard render. The rendered board remains planning-only until explicit runtime admission activates the storyboard control profile.
- `L05` revised: `@` is a structured asset-mention operation, not a permanent lexical handle. UI mention, plain-text surrogate, and API binding are surface-specific. A clear single-subject asset mention may act directly as a grammatical subject; ambiguous multi-subject material requires a compact qualifier.
- `L06`: First-Frame Continuation, First/Last Frames, and Extend have distinct authority contracts. Obey explicit user assignment; ask before freezing the Spine when assignment is ambiguous.
- `L07`: Eight panels are valid when evidence-derived. Only missing provenance, under-sampling, filler, grid-driven count, or director-intent violation is defective.
