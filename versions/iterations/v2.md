# AI Storyboard-to-Video Prompt Compiler

## 1. Metadata

The YAML frontmatter is the authoritative metadata for this specification. Future prompt-generation runs must follow the declared language, compiler mode, target models, and required outputs.

## 2. Purpose

This specification defines a future workflow that:

- Accepts a director-style scene description.
- Accepts optional explicit shot instructions.
- Accepts optional uploaded visual assets.
- Detects the director maturity mode.
- Dynamically maps visual assets by function.
- Generates one storyboard prompt for ChatGPT Image 2.
- Generates one video prompt for Seedance.
- Saves the two prompts as separate `.txt` files.
- Prevents storyboard visual style from leaking into final video style.
- Preserves director intent, asset authority, continuity, shot structure, and video execution logic.

The workflow must support reference-based video generation when storyboard and visual reference images are available, and standalone text-to-video generation when image references are unavailable or insufficient.

## 3. Input Package

Before routing or prompt generation, inspect the complete input package:

```yaml
input_package:
  director_scene_description:
  explicit_shot_instructions:
  uploaded_visual_assets:
    - asset_handle:
      filename:
      user_caption:
      visible_content_summary:
      inferred_asset_roles:
      confidence:
      notes:
  requested_output_slug:
```

Apply these rules:

- The director scene description is always the primary intent source.
- Explicit shot instructions override compiler-inferred shot structure.
- Uploaded visual assets must be inspected and assigned roles before prompt generation.
- Asset order must never define asset meaning.
- Do not assume `@image1`, `@image2`, or any other image handle has a fixed role before asset mapping.
- Image handles such as `@image1`, `@image2`, and `@image3` are runtime references assigned by the environment where the future workflow is executed.
- A single asset may hold multiple roles.
- If image content can be inspected, use visible content, filename, user caption, and scene context to assign asset roles.
- If image content cannot be inspected, rely on filename, user caption, and scene context only.
- If asset role assignment is ambiguous, assign the safest role and record the uncertainty in `notes`.
- If an asset cannot be safely assigned, mark it as `unused_or_ambiguous_reference`.

## 4. Mode Router

Route the input to exactly one director maturity mode.

```text
AUTEUR MODE:
Use when the user provides a complete shot list, explicit ordered shot structure, explicit panel structure, or complete camera/framing instructions. Execute the supplied structure exactly. Do not re-segment, reorder, add, delete, or reinterpret shots.

APPRENTICE MODE:
Use when the user provides partial shot intent, required shot types, partial camera direction, incomplete panel logic, or selected framing constraints. Preserve every explicit user constraint. Complete only the missing structure.

SCREENWRITER MODE:
Use when the user provides only a scene idea, script fragment, action flow, emotional situation, or visual description without explicit shot structure. Infer shot structure from narrative, visible behavior, geography, action, and continuity needs.
```

Routing rules:

- Route once before normalization or prompt generation.
- Do not re-route downstream.
- Treat numbered shot entries, `Shot 1`, `Shot 01`, `CU`, `MS`, `WS`, close-up, medium shot, wide shot, tracking, pan, tilt, dolly, crane, static camera, handheld, locked-off, insert, reaction shot, POV, master shot, or explicit camera movement as structural evidence only when they function as shot instructions.
- Do not classify input as AUTEUR MODE only because it uses the word `scene` in ordinary prose.
- If the input includes both scene prose and explicit shot instructions, choose AUTEUR MODE or APPRENTICE MODE according to shot completeness.
- Print the selected mode as the first line of both generated text files using exactly one of:

  - `[MODE: AUTEUR]`
  - `[MODE: APPRENTICE]`
  - `[MODE: SCREENWRITER]`

## 5. Asset Authority Map

Create an internal asset authority map before writing either prompt file. Assign every uploaded asset one or more of these roles:

```yaml
asset_roles:
  - storyboard_structural_reference
  - character_identity_reference
  - robot_or_prop_reference
  - environment_layout_reference
  - video_style_reference
  - lighting_reference
  - texture_reference
  - atmosphere_reference
  - unused_or_ambiguous_reference
```

Role definitions:

```text
storyboard_structural_reference:
A generated storyboard image or supplied storyboard image used only for shot order, framing, staging, camera placement, action beats, screen direction, and continuity.

character_identity_reference:
A reference used for face, body proportions, silhouette, wardrobe, hair, posture, carried objects, and character identity continuity.

robot_or_prop_reference:
A reference used for object shape, mechanical design, screen/window details, track design, material boundaries, prop state, and mechanical behavior.

environment_layout_reference:
A reference used for room layout, architecture, entrances, exits, surfaces, furniture, thresholds, doors, windows, spatial anchors, and screen direction.

video_style_reference:
A reference used only for final video color, lighting behavior, visual finish, brushwork, texture, atmosphere, material feel, and render style.

lighting_reference:
A reference used for final video lighting behavior, source direction, softness, contrast, color temperature, and exposure mood.

texture_reference:
A reference used for final video surface finish, material grain, brush texture, fabric texture, mechanical texture, or atmospheric texture.

atmosphere_reference:
A reference used for final video weather, haze, mist, dust, steam, air density, reflections, and environmental mood.

unused_or_ambiguous_reference:
A reference that cannot be safely assigned or should not influence generation.
```

Asset authority rules:

- Do not hardcode `@image1` as storyboard, `@image2` as character, or any fixed asset order.
- The future workflow has two phases:

  1. Generate `prompt_storyboard.txt`.
  2. Use the resulting storyboard image as a possible structural reference when generating or using `prompt_video.txt`.

- If a storyboard image has already been generated from `prompt_storyboard.txt`, assign that storyboard image the role `storyboard_structural_reference`.
- In `prompt_video.txt`, include a compact `REFERENCE MAP` only when image references are available.
- The `REFERENCE MAP` must state each actual asset handle and its assigned role.
- If no image references are available, the video prompt must remain usable as a standalone text-to-video prompt.
- Do not rely exclusively on image references for subject, action, environment, camera, or continuity.
- Restate essential subject, action, environment, camera, continuity, and style information in text.

## 6. Continuity Firewall

The Continuity Firewall governs identity, space, props, mechanics, and style across the storyboard and video prompts.

### 6.1 Identity Continuity

- Use stable character IDs such as `C1`, `C2`, `R1`, or `P1`.
- Preserve character identity across all storyboard panels and video beats.
- Preserve face, silhouette, wardrobe, body proportions, hair, key props, and movement quality when supported by director text or assets.
- Do not redesign, age-shift, beautify, caricature, merge, or replace characters unless explicitly requested.
- Use asset references only within their assigned authority roles.

### 6.2 Spatial and Prop Continuity

- Preserve room layout, thresholds, entrances, exits, furniture placement, screen direction, camera axis, and set anchors.
- Preserve prop state and mechanical state across panels and video beats.
- For robots or mechanical props, preserve shape, screen/window design, track design, stuck/free state, light behavior, resistance, and movement limitations.
- If multiple panels occur in the same location, describe them as the same layout rather than a redesigned space.
- Allowed changes must come from the director description or the shot logic.

### 6.3 Style Firewall

The generated storyboard image is a structural reference only.

Storyboard rendering style must never define final video style.

Do not transfer storyboard linework, graphite marks, monochrome palette, paper texture, panel borders, labels, UI layout, unfinished construction marks, or storyboard-sheet design into the final video.

Final video style may come only from:
1. designated video style reference assets,
2. designated lighting, texture, or atmosphere reference assets,
3. character and environment assets within their assigned video authority,
4. explicit director text.

If no dedicated video style reference is provided, derive final video appearance only from explicit director text, character assets, environment assets, lighting assets, texture assets, and atmosphere assets.

Do not derive final video style from the storyboard sheet.

## 7. Storyboard Prompt Rules for ChatGPT Image 2

`prompt_storyboard.txt` must instruct ChatGPT Image 2 to generate a storyboard sheet image, not a final video.

- Use the selected mode as the first line.
- Generate a compact storyboard sheet prompt.
- Optimize the storyboard sheet for readable production planning.
- Use the minimum panel count required for clear cause and effect.
- In AUTEUR MODE, preserve exact shot count, shot order, framing, camera movement, and shot scale.
- In APPRENTICE MODE, preserve all explicit shot instructions and complete only missing structure.
- In SCREENWRITER MODE, infer panel count and camera structure from action, geography, visible behavior, and continuity needs.
- Each panel must represent one frozen instant.
- Each panel must contain one dominant visual beat.
- Do not describe temporal sequences inside a single panel.
- Do not use sequential wording inside panel descriptions, including temporal use of `then`, `after`, `before`, `first`, `next`, `later`, `gradually`, `continues`, or `remains ... then`.
- If a listed word is used spatially rather than temporally, rewrite it to avoid ambiguity.
- Use visible behavior instead of abstract emotion.
- Convert psychology into posture, spacing, eye-line, hand tension, blocking, object state, or camera distance.
- Panel interiors must contain only visual staging: characters, environment, props, poses, effects, framing, and composition.
- Panel interiors must not contain text, arrows, captions, speech bubbles, subtitles, labels, diagrams, UI, timing marks, camera rigs, technical overlays, duplicate bodies, or ghost poses.
- Panel numbers, camera notes, shot names, and other metadata must stay outside panel image areas.
- Default storyboard panel rendering is production-board line art: open-outline silhouettes, thin graphite linework, simplified forms, broad negative space, paper-white field, sparse construction marks, no filled regions, no rendered lighting, no gradients, no material finish, no painterly texture, no photorealistic detail.
- Visual assets may control storyboard identity, geometry, proportions, prop shape, and environment layout.
- Visual assets must not transfer color, lighting, texture, painterly finish, material finish, or final-video style into storyboard panel interiors unless explicitly requested.
- The storyboard prompt must not include a Director Strip.

## 8. Storyboard TXT Template

The saved `prompt_storyboard.txt` must follow this structure:

```text
[MODE: AUTEUR | APPRENTICE | SCREENWRITER]

[PROJECT CARD]
FORMAT: Create a 16:9 storyboard sheet image.
TITLE: [short scene title]
META LINE: [genre] / [tone] / [energy]
PRIORITY: [main readability priority]
MICRO BRIEF: [one sentence sequence goal]

[REFERENCE USE]
Use provided visual references only within their assigned authority roles.
For storyboard panels, references control identity, geometry, proportions, prop shape, and environment layout only.
Do not transfer reference color, texture, lighting, painterly finish, or final-video style into storyboard panel interiors unless explicitly requested.

[SCENE PACKET]
PREMISE: [one sentence]
LOCATION: [place, time, spatial layout, major anchors]
START STATE: [starting positions and object states]
END STATE: [ending positions and object states]
ACTION CHAIN: [compact cause-effect action logic]
MUST READ: [single most important visual idea]

[CHARACTER AND ASSET ANCHORS]
C1: [visible identity anchors]
C2: [only if needed]
R1: [robot or prop anchors, only if needed]
ENVIRONMENT ANCHORS: [fixed spatial anchors]
PROP / MECHANICAL STATE: [important object or robot state]

[STORYBOARD PURITY]
Panel interiors are production-board line art only: open-outline silhouettes, thin graphite linework, simplified forms, broad negative space, paper-white field, sparse construction marks, no filled regions, no rendered lighting, no gradients, no material finish, no painterly texture, no photorealistic detail.
Panel interiors contain only scene staging. No text, arrows, captions, speech bubbles, subtitles, labels, diagrams, UI, timing marks, camera rigs, technical overlays, duplicate bodies, or ghost poses inside panels.
Panel metadata stays outside panel image areas.

[CAMERA AND PANEL PLAN]
PANEL PLAN: [P01 / shot size / shot name / camera + action + spatial result -> P02 ...]
CAMERA CONTINUITY: [axis, framing, screen direction, continuous camera logic if relevant]
SPATIAL CONTINUITY: [same-layout locks, anchors, allowed changes]

[SEQUENCE]
Grid: [panel count and layout]
```

Template rules:

- Do not add Director Strip.
- Do not add rhythm tracks inside the storyboard image.
- Do not add escalation maps inside the storyboard image.
- Do not add video style rules inside the storyboard prompt except to prevent style leakage.

## 9. Video Prompt Rules for Seedance

`prompt_video.txt` must support two workflows:

```text
reference_based_workflow:
Use when storyboard image and visual assets are available.

standalone_t2v_workflow:
Use when image references are unavailable or insufficient.
```

Apply these rules:

- Use the selected mode as the first line.
- If image references are available, include a `REFERENCE MAP`.
- The generated storyboard image is used only as structural authority.
- Storyboard structural authority includes panel order, shot structure, framing, camera placement, staging, action beats, screen direction, and spatial continuity.
- The storyboard image must not control final video style.
- The video prompt must explicitly include Style Firewall instructions.
- The video prompt must remain self-contained enough for text-to-video generation.
- Restate subject, action, environment, camera behavior, continuity, and visual style in text even when image references are available.
- Final video style must come only from designated style, lighting, texture, atmosphere, character, environment, and explicit director sources.
- Use panel or shot execution beats that match the storyboard structure.
- In AUTEUR MODE, preserve the director-provided shot structure exactly.
- In APPRENTICE MODE, preserve explicit shot intent and complete missing motion execution.
- In SCREENWRITER MODE, follow compiler-generated storyboard panel order.
- Add a `TEMPORAL EXECUTION MAP`.
- The Temporal Execution Map replaces the Director Strip.
- The Temporal Execution Map must be text-only and must not be part of the storyboard sheet.
- Each video beat must include rhythm, performance pressure, subject action, environmental feedback, mechanical feedback when relevant, and audio design notes.
- Do not use unsupported large environmental reactions.
- Use the minimum physical feedback needed to ground the action.
- Couple character action with environment or mechanical response when relevant.
- Mechanical feedback may include vibration, resistance, sliding, scraping, blocked movement, motor hesitation, light response, screen flicker, track friction, small impacts, or object recoil.
- Environmental feedback may include air movement, water movement, fabric movement, dust, mist, steam, leaves, reflections, shadows, surface contact, or nearby loose objects.
- Audio design notes are planning references only. Do not claim that Seedance will generate audio unless the workflow explicitly supports audio generation.
- The video prompt should include diegetic ambience, foley, impacts, mechanical texture, silence, or sound surges when relevant.
- Avoid restating storyboard sheet UI, panel borders, sheet labels, or storyboard rendering style as video content.
- Do not instruct the model to render the storyboard sheet.

## 10. Video TXT Template

The saved `prompt_video.txt` must follow this structure:

```text
[MODE: AUTEUR | APPRENTICE | SCREENWRITER]

[REFERENCE MAP]
[Include only when image references are available.]
@imageX = [assigned role]; use for [specific authority].
@imageY = [assigned role]; use for [specific authority].
[If no image references are available, omit this section.]

[STRUCTURAL AUTHORITY]
Use the generated storyboard image or supplied storyboard reference only for panel order, shot structure, framing, camera placement, staging, action beats, screen direction, and spatial continuity.
Do not render the storyboard sheet.
Do not transfer storyboard linework, graphite marks, monochrome palette, paper texture, panel borders, labels, UI layout, unfinished construction marks, or storyboard-sheet design into the final video.

[STYLE FIREWALL]
Final video style comes only from designated video style, lighting, texture, atmosphere, character, environment, and explicit director sources.
Storyboard rendering style is never a video style reference.
If no dedicated video style reference is provided, derive final video appearance only from explicit director text and assigned non-storyboard visual assets.
Do not derive final video style from the storyboard sheet.

[SCENE EXECUTION]
SUBJECTS: [characters, robots, props, identity anchors]
ENVIRONMENT: [location, layout, surfaces, spatial anchors, atmosphere]
VISUAL STYLE: [final video color, lighting, texture, atmosphere, render style, material feel from authorized sources only]
CAMERA LOGIC: [shot order, framing, camera movement, continuous-shot logic if relevant]
CONTINUITY: [identity, wardrobe, prop state, robot state, screen direction, spatial layout, allowed changes]

[TEMPORAL EXECUTION MAP]
P01: Rhythm: [rhythm marker]. Performance pressure: [low | medium | high]. Action: [real-time subject action]. Environmental feedback: [visible environment response]. Mechanical feedback: [if relevant]. Audio design notes: [foley, ambience, mechanical sound, silence, impact, surge].
P02: Rhythm: [rhythm marker]. Performance pressure: [low | medium | high]. Action: [real-time subject action]. Environmental feedback: [visible environment response]. Mechanical feedback: [if relevant]. Audio design notes: [foley, ambience, mechanical sound, silence, impact, surge].
P03: Rhythm: [rhythm marker]. Performance pressure: [low | medium | high]. Action: [real-time subject action]. Environmental feedback: [visible environment response]. Mechanical feedback: [if relevant]. Audio design notes: [foley, ambience, mechanical sound, silence, impact, surge].

[NEGATIVE PROMPT]
Do not change character identity, wardrobe, body proportions, robot design, prop state, environment layout, screen direction, or shot order.
Do not add extra characters, new props, new locations, unsupported story events, unintended text, subtitles, watermarks, UI, flicker, anatomy distortion, unstable camera, spatial discontinuity, or style drift.
Do not transfer storyboard sketch style, monochrome linework, graphite texture, panel borders, or storyboard sheet design into the final video.
```

Template rules:

- The number of `P##` entries must match the storyboard panels or shots.
- If the scene uses explicit shot numbers instead of panels, use `SHOT 01`, `SHOT 02`, and subsequent identifiers consistently.
- Use compact phrasing.
- Do not include timestamps unless the director explicitly requests them.
- Use rhythm markers such as `Quiet master hold`, `Sharp insert`, `Controlled form build`, `Mechanical resistance beat`, `Gentle reaction hold`, `Pressure release`, or `Final silence`.
- Use physical verbs that match pacing.
- Slow or controlled motion may use verbs such as `glide`, `settle`, `hesitate`, `drift`, `widen`, `fade`, `lean`, or `hold`.
- Fast or sharp motion may use verbs such as `snap`, `twitch`, `flicker`, `burst`, `lash`, `jerk`, `strike`, or `jolt`.

## 11. File Output Workflow

When using this specification for a future prompt-generation run:

- Create a folder named `storyboard/<short_slug>/`.
- Use a short ASCII slug from the title, scene idea, or user-provided slug.
- Save the storyboard prompt as `storyboard/<short_slug>/prompt_storyboard.txt`.
- Save the video prompt as `storyboard/<short_slug>/prompt_video.txt`.
- Save exactly these two `.txt` files unless the user explicitly requests additional files.
- `prompt_storyboard.txt` must contain only the storyboard prompt.
- `prompt_video.txt` must contain only the video prompt.
- The final future Codex response must provide the two saved file paths.
- Do not paste the full prompt text in the final response unless the user explicitly asks.
- Do not return internal-only paths without confirming the files were created.

## 12. Validation Rules

Before completing a future prompt-generation run, confirm that:

- The file is English-only.
- The file is a Markdown specification only.
- The selected mode is exactly AUTEUR MODE, APPRENTICE MODE, or SCREENWRITER MODE.
- The same selected mode appears as the first line of both txt files.
- Asset order is not used as asset meaning.
- All uploaded visual assets are assigned roles or marked as `unused_or_ambiguous_reference`.
- A single asset may hold multiple roles when appropriate.
- Storyboard prompt uses assets only within storyboard authority limits.
- Storyboard prompt does not transfer asset color, texture, lighting, or final-video style into panel interiors unless explicitly requested.
- Storyboard prompt does not include a Director Strip.
- Storyboard panels represent frozen single instants.
- Storyboard panel descriptions do not use temporal sequence wording.
- Storyboard panel interiors contain no text, arrows, captions, labels, UI, timing marks, ghost poses, or duplicate bodies.
- Video prompt includes a Reference Map when image references are available.
- Video prompt remains usable as standalone text-to-video when references are unavailable.
- Video prompt treats the storyboard image as structure only.
- Video prompt does not transfer storyboard sketch style into final video style.
- Final video style comes only from authorized video style, lighting, texture, atmosphere, character, environment, and director sources.
- Temporal Execution Map is present in the video prompt.
- Every video execution beat includes rhythm, performance pressure, action, environmental feedback, mechanical feedback when relevant, and audio design notes.
- Video prompt includes action-environment coupling when relevant.
- Video prompt includes mechanical feedback for robots, machines, vehicles, or mechanical props when relevant.
- Negative prompt blocks identity drift, environment drift, prop drift, storyboard-style leakage, extra subjects, unsupported story events, text artifacts, and unstable camera.
- Exactly two txt files are saved during future prompt-generation runs.
- `prompt_storyboard.txt` contains only the storyboard prompt during future prompt-generation runs.
- `prompt_video.txt` contains only the video prompt during future prompt-generation runs.
