# Framewright v3.2-v3.4 剩余风险报告

## 1. 总体结论

当前没有阻止 `3.4.0` 发布的规范冲突或回归。剩余风险主要来自尚未开放或尚未实际测试的 Seedance 2.5 surface / model behavior，而不是当前 core 合同缺失。

本报告不授权 generation、retry、prompt 修改或新一轮迭代。

## 2. 运行时风险

### RSK-01 — `@` mention 的 surface 表现差异

不同平台可能将 `@` 显示为缩略图、filename、chip、index，API 还可能完全将 asset binding 放在 prompt 外。当前 `.txt` surrogate 不能保存 interactive chip。

缓解：Run Card 保存 stable role-to-file mapping；core 明确禁止以 filename / order / UI label 定义 authority。

### RSK-02 — 30 秒 capability 不等于 30 秒可靠性

尚无真实 generation evidence 证明高动作负载、多 reference、多 dialogue 或多 state change 的 30 秒 GU 可稳定执行。

缓解：30 秒仅进入 GU Feasibility Gate 作为 ceiling；不作为默认、自动 merge 或 feasibility 证明。

### RSK-03 — 单 board 的高 panel density

13 或 20 个 equal 16:9 panels 在某些 storyboard renderer 上可能缩小 camera carriers、masthead 或 metadata。C01 明确禁止 multi-board，因此当前只能保留一张 board、报告 residual risk，或在存在自然边界时请求 director 批准拆 GU。

缓解：Panel Evidence 不删关键证据；grid 最后决定；blank cells 被允许；拆 GU 需要自然边界与显式批准。

### RSK-04 — C06 初始 Storyboard generation 的工具失败

resolved Storyboard stage 只授权一次初始 generation。若工具不可用、调用失败或结果明显损坏，系统不能自动 retry。

缓解：先保存 prompt；报告失败；retry、修订后重生和 variant 必须取得新授权。

### RSK-05 — Smart Edit source-master 服从度

规范已要求 source video 是 sole editing master，但模型可能在未授权区域发生 motion、timing、occlusion、audio 或 identity drift。

缓解：task schema 强制 `EDIT SCOPE` 与 `CONTENT TO PRESERVE`；真实失败按 reference authority / serialization / model behavior 分类，不自动改 core。

### RSK-06 — Audio / dialogue / subtitle 的平台差异

不同 Seedance 2.5 surface 可能不同时支持 audio reference、audio edit、dialogue control 或 subtitle control；marker 的最佳形式也可能变化。

缓解：只有显式请求才激活对应 policy；先检查 target-surface support；未指定时保持稳定的 ambience + synchronized SFX + no music 默认。

### RSK-07 — Storyboard runtime admission 的渲染污染

即使 authority 已限制，模型仍可能从完整 board 吸收 line style、panel borders、title、sheet geometry 或错误地把 phases 当 cuts。

缓解：runtime admission 可选择 selected panel crops / structural panels / no attachment，并显式 deny sheet 和 final-look authority。

### RSK-08 — Generation evidence 尚无真实样本

本轮没有实际 Seedance 2.5 generation，因此 retry count、credit cost、route reliability、renderer compliance 和 scene-local repair efficacy 都没有 empirical baseline。

缓解：3.4.0 已定义 evidence schema 与六类 root cause；后续只在用户另行授权后记录真实结果。

## 3. 建议的后续验证顺序

在平台开放 Seedance 2.5 且用户另行授权后，建议以最少 generation cost 按下列顺序测试：

1. 一个单主体 Omni Reference，验证 UI mention / TXT surrogate / Run Card mapping；
2. 一个 Smart Edit 小范围替换，验证 sole editing master；
3. 一个 First and Last Frames 或 Extend，验证边界 authority；
4. 一个显式 dialogue / audio scope，验证默认 no-music 与 requested override；
5. 一个 admitted storyboard structural reference，优先使用 selected panels 而非 full board；
6. 最后才测试接近 30 秒的复杂 Long Video。

每项先验证最不确定的 production block；失败时只修最小局部，不把一次成功或失败升级为全局规则。

## 4. 当前发布边界

- 可发布：core specification、Skill entry、Seedance 2.5 adapter、release snapshots、README 与审计文档。
- 不在本轮执行：安装到 repo 外的其他 Skill 副本、真实 generation、retry、credit spend、历史 prompt migration、项目输出重写。
