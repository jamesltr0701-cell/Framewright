# Framewright v3.5 本地实验剩余风险报告

## 1. What is not proven

本轮没有外部生成，因此以下内容仍未被证明：

- Adaptive Questioning 是否在真实创作中持续发现高价值缺口，而不是增加疲劳；
- World-Response Proposal 是否会改善因果可信度，或膨胀成无关 world texture；
- Intent Ledger 的 rationale 是否在真实 revision 中足够有用，且维护成本可接受；
- SCREENWRITER authority confirmation 是否清晰，还是比 v3.4 更繁琐；
- Semantic Preflight 是否真实减少 silent invention 和 compression loss；
- Seedance 2.5 或其他目标模型是否更好执行编译后的 prompt；
- retry、credit cost、服从度和 stochastic failure rate。

## 2. Principal risks

| Risk | Watch for | Lowest-drift response |
|---|---|---|
| Question fatigue | turns increase without changing downstream contracts | tighten Question Value Test or limit adaptive loop to complex scenes |
| Hidden authority expansion | a delegated choice leaks into other decisions or scopes | narrow the ledger scope and require visible confirmation |
| Intentional freedom loss | natural performance/background behavior becomes over-specified | mark `intentional_freedom` and fail Preflight on over-constraint |
| Causal texture clutter | crowd, traffic, damage, or emergency detail obscures the main action | retain only causally persistent state; use one coherent proposal |
| Ledger duplication | assumptions, question queue, delta, or trace become independent records | regenerate them as derived views from the single ledger |
| Rationale overhead | minor decisions receive unnecessary documentation | require rationale only for materially important decisions |
| Capture over-pruning | necessary repetition or observation is removed | preserve stated exemptions and AUTEUR locks |
| Handoff growth | Intent Delta becomes a second script | show current material delta only; never save it by default |
| Legacy evidence confusion | old prompt contracts are mistaken for current rules | keep historical outputs read-only and treat current core as authority |
| Candidate/stable confusion | 3.5 local is mistaken for Desktop/GitHub release | always display `Loaded: Framewright v3.5.0-local` and retain README status block |

## 3. Runtime and adapter risk

The Seedance 2.5 adapter was intentionally not changed. This minimizes drift but means the interaction between richer v3.5 decision state and actual Seedance 2.5 behavior remains ungenerated. A runtime failure must still be classified at the smallest evidenced layer; it is not automatic proof that the Intent Ledger, world state, or Shot Spine is wrong.

## 4. Historical artifact note

Historical prompts were not migrated. Some pre-v3.4 artifacts use older board or reference serialization patterns. They remain useful as creative and continuity evidence, but they are not normative contracts for the candidate. This is an intentional recoverability choice, not a release inconsistency.

## 5. Suggested real-production sample set

Before evaluating promotion, return, or hybridization, cover when practical:

- one character/relationship-led scene;
- one large action or causal world-state scene;
- one AUTEUR or heavily locked scene;
- one real revision cycle.

For each sample, capture which questions changed the result, which felt unnecessary, what material gap remained, whether intentional freedom survived, whether a rationale conflict was caught, user fatigue, and any retry/credit cost. Natural-language feedback is sufficient.

## 6. Rollback

To return to the stable system, switch back to local `main`. The stable 3.4.0 core and immutable snapshot remain untouched, and Desktop/GitHub already remain on 3.4.0. Preserve this branch and its reports as experiment evidence; no deletion is required.

## 7. Promotion boundary

Promotion is not authorized by this implementation. A future promotion requires separate approval, stable `3.5.0` metadata, a formal immutable release snapshot, and verified synchronization of local source, Desktop mirror, and GitHub intended branch. Until then, the only valid status is `3.5.0-local`, unpushed, not released.
