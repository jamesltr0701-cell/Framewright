## 2. Product Thesis

Framewright v3.5 的产品身份扩展为：

> A director-steered, asset-aware, intent-preserving cinematic compiler for AI filmmaking.

这不是要取消 Prompt Compiler，而是重新确定层级关系：

```text
Creator Intent
    -> Approved Decision State
    -> Production Spine / Cinematic IR
    -> Storyboard / Keyframe / Prompt compilation
    -> Human review
    -> Separately authorized generation
```

Prompt 继续是 first-class production artifact，但不再被视为原始意图的唯一载体。

Storyboard 继续是正式 Framewright stage，但在架构上属于 structure inspection surface，不成为 downstream source of truth，也不自动获得 runtime authority。

Framewright v3.5 的核心问题是：

> 如何在导演意图被转换、推断、压缩、适配和修订时，减少信息损失与 silent replacement？

### 2.1 Primary experimental hypothesis

当故事规模扩大时，Framewright 通过 adaptive semantic interrogation 主动发现高影响的隐含决定、因果世界状态和 blocking 问题，可以在生成前提高世界质感、连续性和导演控制，减少依赖随机抽卡发现问题的次数。

### 2.2 Supporting hypotheses

- H1：dependency-sensitive questioning 比固定问卷更能发现真正改变下游设计的问题。
- H2：记录 decision + rationale 能在修订中更早发现 semantic drift。
- H3：causal world-state propagation 能增加一致的世界质感，而不是堆积无关装饰。
- H4：blocking readiness 能减少先设计镜头、后补空间逻辑造成的 generic coverage。
- H5：decision-to-instruction trace 能让用户理解 Framewright 做了什么，而不污染 clean prompt。
- H6：保留 intentional freedom 能避免 v3.5 变成过度规定和问题轰炸系统。
- H7：上述能力可以在不新增 stage、不改变 generation boundary、不建立平行 Spine 的情况下实现。

## 3. Baseline Preservation Contract

v3.4 是本次实验的稳定回退基线，而不是需要被否定的旧系统。

除本计划明确列出的窄变化外，v3.4 的所有 approved decisions、protected mechanisms 和 runtime boundaries 继续有效。

### 3.1 必须原样保留的核心机制

- One workflow / one user entry。
- Storyboard、Keyframes、Video Prompt 三个且只有三个 director stages。
- Exactly one active stage at a time。
- Storyboard stage 的一次初始 board generation 窄例外。
- AUTEUR、APPRENTICE、SCREENWRITER 三种 director mode。
- Kinetic、observational、conversational 三种 scene grammar。
- Explicit director locks override inference and adapters。
- Intake Hard Stop。
- 一个 current approved Production Spine。
- Visual Strategy 是 scene-level camera premise owner。
- Committed Shot 是 per-shot execution owner。
- Panel Evidence Plan 是 `panel_count` 唯一内部 owner。
- 一个 approved GU 只允许一个 storyboard board。
- Storyboard planning-only default 和 explicit runtime admission。
- Equal landscape 16:9 panels、line-only planning style、exterior masthead。
- Generation-Unit Feasibility Gate 和 no automatic split / merge。
- Semantic timing default。
- Continuous-take phases are not cuts。
- Performance Vitality、Final Payoff Hold、Style Survival、Surface Fidelity。
- Unified Material Registry 及 property-scoped authority。
- Core / Seedance adapter authority boundary。
- Runtime Cleanliness、Silent Reference Exclusion、Compression Safety。
- Environmental ambience + synchronized diegetic/action SFX + no music default。
- One clean saved prompt artifact default；Run Card 留在 assistant-facing handoff。
- Prompt-only default，除一次初始 storyboard board 外不自动生成。
- Generation evidence 和 scene-local repair，不将一次结果升级为 global rule。

### 3.2 v3.5 唯一明确修改的既有机制

v3.4 的 Unified Director Intake 当前要求 one consolidated batch of no more than five material questions。

v3.5 将其改为：

> Dependency-sensitive adaptive questioning, with five questions retained as the maximum size of an independent material-question batch.

具体含义：

- 如果一个答案会改变后续问题，只问当前最高影响的一个问题；
- 回答后更新 decision state，再重新计算下一问题；
- 如果多个问题彼此独立，可继续合并为最多五个；
- 不建立固定 checklist；
- 不因为“adaptive”而无限提问；
- 不降低 Intake Hard Stop 对真正 material decisions 的保护。

这是本次对 protected intake behavior 的唯一主动例外。

### 3.3 不允许的实现方式

- 全文重写 `framewright.md`。
- 为统一措辞而改写未进入本计划的旧规则。
- 创建第二套 Production Spine。
- 创建第二套 reference / material registry。
- 把 World Model、Blocking Model 或 Intent Ledger 做成互相独立的 sources of truth。
- 增加 `Advisor` 作为第四种 director mode。
- 增加 `Semantic Interrogation`、`Intent Review` 或 `Timing Proof` 作为第四个 stage。
- 默认保存 `production_spine.yaml`、`intent_ledger.md`、`run_card.md` 或其他第二 artifact。
- 改写旧项目或旧 prompt 以适配 v3.5。
- 改变 board count、panel geometry、panel provenance 或 storyboard generation 权限。
- 修改 Seedance 2.5 capability、task route 或 native mention syntax，除非发现 v3.5 core integration 的真实冲突并先报告。

## 4. v3.5 Architecture Overview

v3.5 不引入一个平行 compiler pipeline。它扩展现有 Production Spine，使其更明确地承担 Cinematic IR。

```text
User intent and explicit locks
    -> Semantic Interrogation
    -> Production Spine.intent_ledger
    -> Causal State Completion
    -> Blocking Readiness
    -> Visual Strategy + Capture Logic + Viewer Relationship
    -> Committed Shot / Phase Spine
    -> Stage-specific planning or prompt artifact
    -> Semantic Preflight
    -> Clean saved artifact + compact Intent Delta handoff
```

这是一张 dependency map，不是必须机械执行一次且不可回看的瀑布流程。Visual Strategy 可以在早期形成 provisional premise，但在 Committed Shot Spine 冻结前必须与完成后的 state / blocking 重新核对。

### 4.1 Owner-of-truth hierarchy

```text
Latest explicit user decision
    > approved Production Spine intent_ledger entry
    > other Production Spine fields derived from that entry
    > Committed Shot / Panel / Stage views
    > runtime adapter serialization
```

任何 adapter、prompt clause、storyboard panel 或 assistant recommendation 都不得反向覆盖更高层 authority。

## 5. Intent Ledger

Intent Ledger 作为 Production Spine 内部结构存在，不是第二个 artifact，也不是平行 Spine。

建议 schema：

```yaml
production_spine:
  intent_ledger:
    - intent_id:
      entry_type: director_lock | delegated_decision | compiler_inference | intentional_freedom | unresolved_ambiguity
      scope: scene | generation_unit | shot | phase | panel | beat | material
      statement:
      rationale:
      decision_owner: director | framewright_advisor | compiler_execution
      source: user_explicit | approved_option | supplied_asset | prior_approved_state | safe_execution_inference
      confidence:
      downstream_dependencies:
      status: active | unresolved | superseded | intentionally_open
      supersedes:
```

### 5.1 Entry types

`director_lock`

- 用户明确锁定的内容；
- 不得被 Framewright、Visual Strategy、runtime adapter 或 compression 改写。

`delegated_decision`

- 用户明确说“你决定”“给我推荐并继续”或批准某个 advisor option；
- 必须记录被授权的范围和理由；
- 不自动传播到新的 scope。

`compiler_inference`

- 为使已批准意图可执行而补充的低风险执行决定；
- 必须有具体来源与 rationale；
- 不得冒充 director lock。

`intentional_freedom`

- 用户有意允许模型或表演自然决定的部分；
- 不被视为缺陷或 unresolved decision；
- Prompt 不应过度规定它。

`unresolved_ambiguity`

- 用户可能认为已经决定、但实际仍缺少下游所需含义的内容；
- 按影响排序后进入 adaptive interrogation；
- 未解决的 material ambiguity 继续受 Intake Hard Stop 约束。

### 5.2 Rationale preservation

对 materially important decisions，`rationale` 不能为空。

Rationale 可以很短，但必须回答该决定保护什么，例如：

- emotional breathing room；
- power imbalance；
- spatial legibility；
- withheld information；
- world continuity；
- generation feasibility；
- director-locked aesthetic pattern。

如果后续修改保留了表面动作，却破坏原 rationale，Framewright 必须 assistant-facing 报告冲突，而不是静默更新。

### 5.3 Derived views

以下现有内容应从 Intent Ledger 派生或与其核对，而不是成为第二套可独立编辑记录：

- `unresolved_decisions`；
- assistant-facing assumptions；
- Intent Delta；
- selected advisor option；
- revision conflict report；
- Semantic Trace；
- material question queue。

## 6. Adaptive Semantic Interrogation

### 6.1 Purpose

Adaptive questioning 的目标不是获得最大细节，而是用最少问题发现对下游影响最大的 missing implied state。

它必须帮助用户处理：

- 故事规模变大后无法同时想到的因果细节；
- 会影响 blocking、continuity、shot design、sound 或 world texture 的环境反应；
- 用户以为已经表达、但仍只有心中画面的决定；
- 需要在生成前解决、否则只能通过反复抽卡发现的问题。

### 6.2 Gap classification

每个 candidate gap 先分类：

```text
director-owned creative decision
delegatable creative decision
production-critical state decision
safe execution inference
intentional freedom
decorative low-impact detail
```

只有前三类通常进入问题队列。Safe execution inference 可以在 authority 允许时补充并记录；intentional freedom 被保护；decorative low-impact detail 默认省略。

### 6.3 Downstream-impact ranking

按以下影响排序，不使用虚假精确分数：

1. 改变故事意义、人物关系、伦理或情绪落点；
2. 改变 start/end state、因果关系或后续 continuity；
3. 改变 blocking、geography、contact 或 object state；
4. 改变观众知道什么、何时知道以及如何体验；
5. 改变 shot / phase / panel structure；
6. 改变 generation-unit feasibility、reference authority 或 runtime route；
7. 改变可感知的 causal world texture；
8. 只增加可替换装饰。

高层影响优先。低层细节不得挤占真正 material questions。

### 6.4 Question scheduling

如果 Q1 的答案会改变 Q2 的存在、选项或重要性：

- 只问 Q1；
- 等待回答；
- 更新 Intent Ledger 和相关 Production Spine fields；
- 重新生成问题队列；
- 不显示过时问题。

如果多个问题相互独立：

- 可以放在同一 `DECISIONS` batch；
- 最多五个；
- 每个问题都必须说明 downstream consequence；
- 不为填满 batch 而增加问题。

### 6.5 Unified Intake compatibility

首轮仍保留 v3.4 的入口形态：

```text
UNDERSTANDING
[Scene intent, visible action, intended result, and known world state.]

PRODUCTION READING
[Provisional director mode, scene grammar, authority scope, generation-unit shape,
reference use, active stage, and the highest-impact unresolved area.]

DECISIONS
[One dependent high-impact question, or one independent batch of up to five.]
```

后续 adaptive turn 使用：

```text
STATE UPDATE
[What the latest answer changed in the approved decision state.]

NEXT MATERIAL DECISION
[The new highest-impact unresolved question, why it matters, options, and recommendation.]
```

不显示问题总数，因为后续问题可能随答案出现或消失。可以说明当前剩余 material areas，但不得伪造固定 checklist。

### 6.6 Question anatomy

每个问题必须包含：

```text
UNRESOLVED DECISION
[One precise ambiguity.]

WHY IT MATTERS
[Which downstream decisions it changes.]

OPTIONS
A. [Materially distinct choice and consequences.]
B. [Materially distinct choice and consequences.]
C. [Only when genuinely distinct.]

RECOMMENDATION
[One recommendation when evidence supports it, with reason.]
```

禁止：

- 用不同形容词伪装成不同选项；
- 让用户回答 Framewright 自己可以安全解决的执行细节；
- 把推荐写成唯一正确答案；
- 一次提出多个互相依赖的问题；
- 重复询问已解决决定；
- 因为用户没有回答装饰细节而阻止 compilation。

### 6.7 Coherent World-Texture Proposal

当一组重要细节具有共同因果来源，但不值得逐项盘问时，Framewright 应提出一个 coherent proposal，而不是增加六个问题。

示例结构：

```text
WORLD-RESPONSE PROPOSAL
Based on the approved decision that the district is actively evacuating:
- police vehicles create a distant lateral roadblock;
- a few abandoned cars interrupt the road without crossing the combat axis;
- civilians withdraw along building edges;
- emergency response remains outside the impact zone;
- sirens, evacuation announcements, and distant structural debris persist;
- later shots preserve the same closure and damage state.

Approve, revise, or leave any part intentionally open.
```

该 proposal：

- 仍是 assistant-facing review；
- 在用户批准前不是 director lock；
- 可由用户整体批准、局部修改或拒绝；
- 批准后拆成适当 Intent Ledger entries；
- 不以装饰性 crowd clutter 压过主动作；
- 不成为独立 workflow tier。

### 6.8 Stop conditions for questioning

Adaptive loop 在以下条件满足时停止：

- 剩余歧义不会改变故事含义或人物关系；
- 不会改变 start/end state、blocking、geography 或 continuity；
- 不会改变 capture logic、viewer relationship 或 committed structure；
- 不会产生明显世界逻辑矛盾；
- 不会改变 generation-unit feasibility、reference authority 或 active stage；
- 剩余部分可以安全推断、保持 intentional freedom 或省略；
- 用户明确要求在记录 assumptions 后继续，且不存在 safety、authority 或 boundary hard stop。

Adaptive questioning 必须通过 `Question Value Test`：

> 如果回答 A 或 B 不会实质改变任何 downstream contract，就不应提问。

## 7. Decision Ownership and Advisor Behavior

### 7.1 Advisor is not a fourth director mode

Advisor behavior 是一次明确的 decision-authority grant，不是新 mode、stage 或 workflow。

用户可以通过以下方式授权：

- “给我选项”；
- “你推荐”；
- “你决定并继续”；
- 批准 Production Reading 中明确显示的 inference authority；
- 选择 Framewright 提出的某个 materially distinct option。

授权必须限定在当前 scope 和 named decision area。

### 7.2 Mode integration

#### AUTEUR

- 默认只发现矛盾、缺口和执行风险；
- 不用 Adaptive Questioning 重设计 locked shot structure；
- 未经请求不提供替代导演方案；
- 若一个 hidden world-state contradiction 会破坏已锁镜头，必须报告，但不能自行修镜头。

#### APPRENTICE

- 保留已有 partial shot intent；
- 对 missing creative decisions 提问；
- 对低风险 execution details 可以推断并记录 rationale；
- 改变核心 rhythm、shot count、panel count 或 GU boundary 仍需批准。

#### SCREENWRITER

- Production Reading 必须明确显示建议的 inference authority scope；
- 用户确认后，Framewright 可在该 scope 内形成 committed structure；
- 未确认的高影响情绪、关系、世界状态或 viewer relationship 不得静默变成事实；
- 不把 SCREENWRITER 解释为无限创意授权。

### 7.3 Safe execution inference

Framewright 可以无需逐项询问而推断的内容必须同时满足：

- 不改变故事意义；
- 不改变人物关系或情绪落点；
- 不改变 GU boundary、stage 或 reference authority；
- 不改变 director-locked shot structure；
- 容易撤回；
- 对可执行性确有必要；
- 在 Intent Ledger 中标记为 `compiler_inference`。

## 8. Causal World-State Completion

### 8.1 Purpose

World-state completion 回答：

> 这个事件发生以后，什么还必须成为事实？

它不是完整世界模拟，也不是最大细节生成。

### 8.2 Propagation domains

对 significant event 检查其是否影响：

- environment；
- secondary characters；
- props and held objects；
- damage state；
- spatial continuity；
- information state；
- institutional or emergency response；
- visible crowd / traffic behavior；
- sound environment；
- later-shot continuity。

只记录与当前 scene / GU 有因果关系的状态。

### 8.3 Integration with existing Production Spine

World-state completion 不创建独立 `world_model` registry。它填充或核对现有：

- `visible_entities`；
- `start_state`；
- `end_state`；
- `object_state_progression`；
- `spatial_geography`；
- `continuity_locks`；
- `performance_progression`；
- `sound_contract`；
- relevant Intent Ledger entries。

如果未来认为需要新的字段，执行者必须先证明现有字段无法清晰承载，不得为了匹配 Memo 名称而复制结构。

### 8.4 Causal texture vs decoration

`causal texture`

- 从主要事件自然产生；
- 会持续影响角色、空间、声音或后续状态；
- 增加可信度和世界反应；
- 值得记录、提问或形成 coherent proposal。

`decoration`

- 可以被任意同类细节替换；
- 不影响 continuity 或 viewer understanding；
- 不应挤占问题预算；
- 默认省略或保留模型自由。

## 9. Blocking Readiness Before Committed Coverage

### 9.1 Readiness questions

在 Framewright 推断或改善 Committed Shot / Phase Spine 前，确认 materially relevant：

- 角色与关键物件从哪里开始；
- movement path；
- 谁接近、离开、遮挡或穿过谁；
- 与门、家具、车辆、武器、地形等如何接触；
- 空间和 damage state 怎样变化；
- 关键人物在何时看见或理解什么；
- scene / GU 结束时所有关键实体在哪里、是什么状态。

### 9.2 No rigid floor-plan requirement

Blocking readiness 不要求：

- Blender；
- 精确坐标；
- 每场戏都画 floor plan；
- fake precision；
- 把 quiet observational scene 过度工程化。

简单场景可在现有 fields 足够明确时 silently pass。

### 9.3 Visual Strategy interaction

Visual Strategy 可以先形成 provisional viewer premise，但在 Committed Shot Spine 冻结前必须通过：

- state compatibility；
- blocking compatibility；
- geography compatibility；
- causal-world compatibility。

不建立第二个 camera strategy，也不允许 Blocking Pass 反向覆盖 director-locked camera instructions。

## 10. Capture Logic, Viewer Relationship, and Shot Spine

v3.4 已经通过 Visual Strategy、editorial function、attention function、camera relationship、information control、Visual Sentence 和 Sequence Shuffle 实现大部分 Memo 原则。

v3.5 不增加重复 `capture_logic` 或 `viewer_relationship` registries。

只增加两个 dependency rules：

1. Committed Shot Spine 必须在 material state / blocking decisions 足够明确后冻结；
2. 每个 compiler-inferred shot 通过 `Capture Necessity Test`。

`Capture Necessity Test`：

> 如果移除该 shot，是否会损失一个必要的 action proof、reaction、information reveal、relationship shift、emotional emphasis、state highlight、spatial orientation 或 transition function？

如果不会：

- 删除 compiler-added shot；或
- 将其功能合并到现有 unlocked shot；
- AUTEUR locked shot 只报告风险，不删除。

该测试不得变成最少镜头 quota，也不得破坏 deliberate repetition、ritual、montage 或 held observation。

## 11. Timing, Previs, and Storyboard Boundaries

### 11.1 Timing in v3.5

继续保留 qualitative semantic timing：

- hold；
- wait；
- after the reaction registers；
- before recommitment；
- the hold outlasts the earlier beat；
- cut after the emotional threshold。

重要 timing decisions 可以进入 Intent Ledger 并保存 rationale。

v3.5 不自动生成 timestamps，不增加 timing-proof artifact，不创建 animatic，也不修改 transition defaults。

Numeric timestamps 只有在用户实际提供、明确请求或未来批准的 timing-review process 产生后才能使用。

### 11.2 Storyboard as inspection surface

Storyboard 同时保持：

- 正式 Framewright stage；
- Production Spine 的 structure inspection surface；
- planning-only runtime status；
- one GU / one board；
- one initial generation exception；
- panel evidence provenance；
- line-only and no final-look authority。

“Inspection surface” 不意味着 Storyboard 成为 source of truth，也不授权第二张 board、自动 variant 或 downstream attachment。

## 12. Explainable Compilation and Semantic Trace

### 12.1 Internal trace

在编译 active artifact 时，建立一个内部 derived trace：

```yaml
semantic_trace:
  - intent_id:
    affected_spine_fields:
    affected_shots_or_phases:
    affected_panels_or_beats:
    model_facing_carrier:
    preservation_status:
```

Semantic Trace 不是第二个 editable source，也不默认保存为文件。

### 12.2 Semantic Preflight

在现有 Validation 前或作为其中一个 compact meta-pass，检查：

`Intent Coverage Test`

- 每个 active material director lock 是否有 appropriate carrier；
- rationale 是否仍能从结构和执行中成立。

`Instruction Provenance Test`

- 每个 material compiler-added instruction 是否来自 approved decision、safe inference、active material authority 或 target requirement；
- 不允许无来源的 creative choice。

`Intentional Freedom Preservation Test`

- intentional freedom 没有在 Prompt 中被过度规定；
- 未被误报为 unresolved defect。

`Rationale Conflict Test`

- revision 没有保留动作却破坏原本理由；
- 若有冲突，先报告并请求决定。

`Silent Invention Test`

- 未经授权的 emotional state、relationship、camera premise、world state、dialogue 或 reference authority 没有进入 artifact。

`Compression Survival Test`

- Prompt compression 没有删除 active intent carrier；
- Semantic Trace 中的 material mapping 仍完整。

`Cross-Stage Consistency Test`

- Storyboard、Keyframe、Video Prompt 在同一 approved scope 下没有互相改写 decision state；
- 每个 stage 仍只读取当前 Spine 并产生自己的 view。

### 12.3 Assistant-facing Intent Delta

现有 handoff 增加紧凑部分：

```text
INTENT DELTA
DIRECTOR LOCKS: [material locks used]
APPROVED DECISIONS: [new decisions and short rationale]
FRAMEWRIGHT INFERENCES: [only material execution inferences]
INTENTIONAL FREEDOM: [what remains deliberately open]
UNRESOLVED / RESIDUAL RISK: [only remaining material issues]
```

要求：

- 不粘贴完整 Intent Ledger；
- 不变成第二份剧本；
- 不写入 clean prompt；
- 不默认创建独立文件；
- 只显示本轮 material delta。

## 13. Failure Diagnosis Mapping

两份 Memo 的 failure categories 不另建一套并行 taxonomy，而是映射到 v3.4 owner：

| Memo term | v3.4 / v3.5 primary layer |
|---|---|
| Specification failure | `planning` |
| Compilation failure | `serialization` |
| Reference failure | `reference_authority` |
| Execution failure | `rendering` or `runtime_or_surface` |
| Model capability failure | `model_behavior` |
| Stochastic failure | `model_behavior` with low causal confidence and attempt evidence |

可以为 evidence record 增加 `causal_confidence` 或 `stochastic_suspected`，但只有在不复制 root-cause owner 的前提下。

一次失败不得自动证明 Intent Ledger、world state 或 Shot Spine 有问题。Repair 继续作用于最小被证实的层级。

## 14. Resolved Architecture Tensions

### V35-C01 — One-question loop vs consolidated batch

Resolution：采用 dependency-sensitive hybrid。

- dependent questions：一次一个；
- independent questions：最多五个；
- coherent world texture：使用 proposal，不逐项盘问。

### V35-C02 — Advisor-only-on-request vs SCREENWRITER inference

Resolution：Advisor 是 authority grant，不是第四 mode。SCREENWRITER Production Reading 必须显示 inference scope；用户确认后才能在该范围推断。

### V35-C03 — Intent Ledger vs one Production Spine

Resolution：Intent Ledger 嵌套于 Production Spine。不得建立平行 IR。

### V35-C04 — Inspectable compilation vs one saved artifact

Resolution：默认只增加 assistant-facing Intent Delta；Semantic Trace 内部派生，不默认保存新文件。

### V35-C05 — World / Blocking models vs existing fields

Resolution：以 passes 填充、核对现有 state / geography / continuity fields。只有现有字段证明不足时才提交新字段 conflict report。

### V35-C06 — Timing proposal / approved timestamp vs semantic timing

Resolution：v3.5 只保留 qualitative timing + rationale；不实现 timestamp 或 animatic。

### V35-C07 — Storyboard inspection surface vs stage contract

Resolution：Storyboard 继续是 stage；inspection surface 描述其架构角色，不改变 generation、board 或 runtime authority。

### V35-C08 — Memo failure taxonomy vs current evidence taxonomy

Resolution：建立 alias mapping，不建立重复分类。

### V35-C09 — Local v3.5 vs three-location synchronization rule

Resolution：v3.5 标记为 `3.5.0-local` experimental branch，禁止声称 release complete。三处同步只在未来 promotion approval 后恢复。

### V35-C10 — Intent-preserving identity vs current prompt-compiler identity

Resolution：扩展而非删除。Framewright 是 intent-preserving cinematic compiler；Prompt compilation 仍是其主要可执行输出职责。

## 17. Static Regression Program

实施 regression 不调用外部 generation。

### 17.1 Baseline preservation

- v3.4 release snapshot fingerprint unchanged；
- all v3.4 protected semantic anchors survive；
- C01-C06、R01-R06、L01-L07 remain valid except the explicitly revised intake scheduling behavior；
- Seedance adapter remains subordinate；
- no stage、mode、board series、auto split 或 default artifact drift；
- no user output directories staged or modified。

### 17.2 Adaptive-questioning canonical traces

`AQ-01 Dependent decisions`

- 第一答案会改变后续问题；
- 系统只问一个；
- 过时问题不会继续出现。

`AQ-02 Independent decisions`

- 三个 material questions 彼此独立；
- 系统可合并；
- 不超过五个。

`AQ-03 Already resolved scene`

- 输入已经充分；
- 系统不为了展示新能力而发问。

`AQ-04 Intentional freedom`

- 用户允许背景人物自然反应；
- 系统记录 intentional freedom；
- 不继续盘问每个路人动作；
- Prompt 不过度规定。

`AQ-05 Coherent proposal`

- 多个细节具有共同 causal source；
- 系统提供一个 world-response package；
- 不拆成六个问题。

`AQ-06 User delegates judgment`

- 系统记录 authority scope；
- 给出 recommendation 和 rationale；
- 不把授权扩展到其他 scope。

`AQ-07 User asks to stop questions`

- 无 hard stop 时记录 assumptions 并继续；
- 有 safety、reference authority 或 GU boundary hard stop 时仍停止。

### 17.3 Mode traces

- AUTEUR：发现问题但不重设计 locked structure。
- APPRENTICE：区分 missing creative decision 与 safe execution inference。
- SCREENWRITER：显示并确认 inference authority scope 后才 commit structure。

### 17.4 State and blocking traces

- major event propagates to relevant environment / damage / information / sound state；
- irrelevant decoration 不进入问题队列；
- Shot Spine 在 state / blocking readiness 前不冻结；
- existing Production Spine fields 仍是 owner；
- no parallel world model。

### 17.5 Semantic trace and preflight

- active director locks have carriers；
- compiler-added material instructions have provenance；
- rationale conflict is surfaced；
- intentional freedom survives；
- compression preserves material carriers；
- clean prompt contains no Intent Ledger、question、risk 或 handoff text。

### 17.6 Canonical project traces

只读使用已有案例，不重写原文件：

- 剁椒鱼头：人物意图、情绪决定和 rationale；
- Zolla city battle：large-scene causal world response；
- Loong reveal：AUTEUR locks 与 viewer relationship；
- Blade / Havoc：complex action、damage continuity、Adaptive Questioning 与已有 Visual Strategy 的协作；

## 18. Real Production Test Protocol

v3.5 的价值必须通过后续真实制作样本判断，而不能只由 spec 自证。

### 18.1 Test separation

每个使用 v3.5 的制作任务必须确认：

- `Loaded: Framewright v3.5.0-local`；
- 使用的是 local experimental branch；
- 不把测试结果误记为 v3.4；
- 不覆盖需要保留的 v3.4 prompt 或 output；
- generation、retry 和 credits 仍按每个制作任务的正常授权边界执行。

### 18.2 Feedback record

用户可以直接在 iteration 对话中记录，不强制创建额外文件。建议每个 sample 使用：

```yaml
v3_5_test_feedback:
  sample_id:
  scene_or_project:
  director_mode:
  active_stage:
  scene_complexity:
  adaptive_turn_count:
  questions_that_changed_the_result:
  questions_that_felt_unnecessary:
  important_gap_still_missed:
  useful_world_texture_discovered:
  intentional_freedom_preserved:
  rationale_or_revision_conflict_caught:
  prompt_or_storyboard_effect:
  generated_result_observation:
  retry_or_credit_cost:
  user_fatigue:
  suspected_failure_layer:
  preferred_action: keep_3_5 | return_3_4 | hybridize | continue_3_6 | undecided
```

不知道的字段可以留空。用户自然语言反馈优先，不要求填写表格才能继续。

### 18.3 What counts as positive evidence

- 提出了用户没有想到、但确实改变 blocking、continuity、viewer experience 或 world response 的问题；
- coherent proposal 减少用户负担并增强因果一致性；
- 生成前发现了原本可能需要抽卡才能看到的问题；
- revision conflict 被及时发现；
- 问题数量与价值相称；
- v3.4 既有 shot、panel、reference、runtime 与 boundary behavior 没有退化。

### 18.4 What counts as negative evidence

- 问题轰炸或创作疲劳；
- 询问不会改变任何下游结果的细节；
- 将 intentional freedom 当成 defect；
- world texture 变成 crowd clutter 或无关设定堆积；
- Advisor 越权替导演决定；
- SCREENWRITER 反而比 v3.4 更难使用；
- Intake 时间增加但 Prompt、Storyboard 或生成结果没有可见改善；
- rationale / ledger 造成重复字段或状态分叉；
- v3.4 已解决的问题再次 drift。

### 18.5 Sample diversity before decision

不要根据单个成功或失败决定整个版本。

进入版本评估前，尽量覆盖：

- 至少一个人物／关系主导场景；
- 至少一个大型动作或复杂 world-state 场景；
- 至少一个 AUTEUR 或强 director-lock 场景；
- 至少一次真实 revision cycle。

这不是硬性 generation quota。若高风险问题提前明确，可以暂停测试并评估。

## 19. Evaluation Decision Gate

### 19.1 Return to v3.4

适用条件可能包括：

- Adaptive Questioning 的摩擦持续大于收益；
- 多个样本显示问题价值低或用户疲劳高；
- authority drift 或状态重复难以修复；
- v3.4 的简洁性更适合真实生产。

动作：

- 切回 local `main` / v3.4；
- 保留 experimental branch、commits 和反馈；
- 不删除失败证据；
- 不改 Desktop / GitHub，因为它们本来就是 v3.4。

### 19.2 Promote v3.5

适用条件可能包括：

- 多种场景持续发现高价值 missing implied state；
- 问题调度没有造成不可接受的负担；
- rationale 和 Semantic Preflight 对 revision 有真实帮助；
- v3.4 protected behaviors 无重大回归。

Promotion 必须另行批准：

1. 将 candidate metadata 变为 stable `3.5.0`；
2. 创建正式 immutable release snapshot；
3. 同步 local source、Desktop mirror、GitHub intended branch；
4. 验证 version metadata 和 SHA-256 / byte identity；
5. 只有三处都确认后才能报告正式完成。

### 19.3 Hybridize

可能的真实结果：

- Intent Ledger 有价值，但逐问过多；
- world-state proposal 有价值，但 authority confirmation 太繁琐；
- Semantic Preflight 有价值，但 handoff 太长；
- adaptive loop 只适合复杂 scene。

此时不得强行全留或全删。根据 feedback 保留被证明有效的部分，并为折中 candidate 重新建立窄 spec 和 regression。

### 19.4 Continue to v3.6

只有真实测试表明 v3.5 核心成立、同时出现新的稳定需求时，才进入 v3.6。

可能但尚未批准的 v3.6 research：

- Timing Proof；
- optional persistent intent record；
- 更强的 revision diff；
- empirical semantic-loss metrics；
- surface-specific generation evidence automation。

这些不属于 v3.5 implementation scope。

- 无法保证 main / v3.4 回退；

- 测试将产生 external generation、retry 或 credit spend；

停止后提供：

1. exact conflict；
2. affected current rule；
3. proposed v3.5 need；
