# Diagnose and preserve a usable take — Framewright craft reference

Use with Core §16 when the director asks for generation diagnosis, repair, or another attempt. Keep the existing failure owners, causal confidence, take disposition, budget, and authorization. This is a set of investigation aids, not another retry system. A poor take does not by itself invalidate the director's idea or the approved shot.

## Begin with what should survive

Separate the director's acceptance decision from technical perfection. Identify useful camera work, performance, identity, timing, or a usable portion of the take before proposing changes. A continuous generation can supply selected pieces of an edit. Do not assume every generated frame must enter the film, or treat cropping/trimming as a failed generation strategy.

Use the existing dispositions: accept, post-fix, local edit, retry, rewrite-or-split, or do-not-generate. A fix that appears easy in post still needs an available tool and evidence that it preserves the intended result. Do not promise a few minutes of repair without inspecting the defect and constraints. The director may keep an imperfection or stop trying.

## Compare approved intent, actual inputs, and observed result

First establish what the director approved, which prompt and material roles actually reached the target, and what the result shows. Label uninspected results as reported. A registry or text-validation PASS does not prove the media bindings, the loading history, or the visual result.

| Symptom | Distinguish before repairing | Smallest useful investigation |
|---|---|---|
| First frame becomes a different angle or pose | Wrong runtime role, wrong uploaded file, contradictory text, or target behavior | Compare admitted image, actual binding, opening clause, and observed initial frames |
| Intermediate pose becomes a stop or opening | Boundary wording versus conditioning influence | Check whether the source is called a first/end frame or an intermediate state; inspect when the pose appears |
| Camera follows a fall without rolling | Missing orientation instruction, ambiguous screen relationship, or failure to realize a clear instruction | Compare horizon/world verticals and body direction with the approved move |
| Action is slow or waits for the camera | Authored timing, sequential wording that should be concurrent, reference pose, or model behavior | Locate the pause in the actual take and compare the relevant action/camera clauses |
| Face, limb, prop, or room changes | Source ownership conflict, wrong input, occlusion, scale, or target inconsistency | Inspect the affected region and its source; separate persistent identity from transient state |
| Light behaves like a switch | Source-change wording versus travel between stable sources | Identify the intended source positions and actual transition; consult the light/sound reference only if needed |
| Extra voice, music, or mechanical sound | Prompt permission, donor audio, target defaults, or sampling behavior | Locate the cue and compare it with the approved sound source and active audio inputs |
| Repeated failure after revision | Wrong diagnosis, ineffective control, platform limitation, or stochastic variation | Compare what actually changed and what stayed fixed; retain competing explanations when evidence is weak |

Map each finding onto Core's existing primary owners: planning, serialization, rendering, reference_authority, runtime_or_surface, or model_behavior. Use a hypothesis with a stated confidence when causality is uncertain. Do not assert private model internals, guarantee that shorter prompts work better, or decide that two similar failures prove a prompt defect.

## Choose a repair that answers the problem

Repair the smallest affected owner: correct a binding error at the material input, clarify omitted motion in serialization, or return an unresolved authored conflict to the director. Do not solve every problem by adding adjectives, deleting action, forcing a close-up, adding anchors, or splitting the shot.

For a diagnostic retry, name the one variable changing and retain unaffected contracts under Core's authorization and budget. If a broader approved rewrite must change several linked conditions, say that it is a rewrite and do not claim a controlled causal experiment. No fixed number of attempts proves a cause, and no default attempt allowance grants spending authority.

Treat an external model tip as a scene-local hypothesis until supported. Technical values, available modes, reference ceilings, and syntax come from the selected versioned adapter or verified surface documentation, never from this craft reference or a different model line.

## Return a useful decision

Explain the observed/reported mismatch, what is already worth preserving, the best-supported explanation and uncertainty, and the smallest next action. Reuse the existing evidence record; do not create an extra file, checklist, or verdict card by default. Stop at the authorized boundary. Only the director accepts a take, changes locked intent, expands generation scope, or grants another paid attempt.
